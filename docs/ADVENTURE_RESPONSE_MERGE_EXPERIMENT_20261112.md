# 이동 응답 병합과 탭 간 펜스 검토

로컬 Chromium에서 기존 보유함 패치 병합과 패치 ID 중심 배열 순회를 각각 반복 측정했다. 각 개체는 간단한 모의 객체이고 패치는 2개다. 100·1,000·10,000·50,000마리에서 기존 평균은 각각 0.032·0.100·1.524·6.084ms, 비교 후보는 0.008·0.042·0.298·1.905ms였다. 브라우저 내부 반복 측정이며 실제 응답 파싱·React 렌더링·운영 기기 체감이나 전체 요청을 측정하지 않았다. 일반적인 크기의 차이가 작고 중복 ID·정렬·삭제 의미를 완전히 검증하지 못했으므로 병합 방식을 바꾸지 않았다.

`cloud-movement-two-tabs.mjs`는 동일 계정의 두 탭에서 A의 이동 요청을 보류한 뒤 B를 새로고침한다. B의 무조건적 진입 펜스로 리비전이 바뀌면 A의 이전 이동은 409가 되고 복구 후 다음 이동은 성공한다. 이 테스트는 실제 브라우저의 모의 API 시험이다. 임시 이동을 무조건 재시도하면 조우·충돌과 중복 처리 위험이 있고, 진입 펜스를 없애면 늦은 요청이 복구 조회 후 저장될 수 있으므로 두 방식 모두 적용하지 않았다. 펜스 충돌을 줄이려면 계정과 탭에 묶인 이동 요청 식별자 및 재접속·저장소 차단 시의 원자적 판정을 별도로 설계하고 실제 D1 경합을 검증해야 한다.
