# 사파리 빈 보상 화면의 진행 복구

기준: c292473 이후, 원본 `7c0881255af5cd51992e513ff93c2f71adbe40e0`.

독립 QA는 203e427 자연 43웨이브 사파리에서 세 조우 뒤 만원 파티의 포획 개체를 놓아주면 보상이 0개이고 다음 버튼이 없어 진행할 수 없다고 보고했다. 같은 저장을 c292473에서 열어도 막혔다. 이 수정에서는 실제 QA 계정 저장에 접근하지 않았고, 같은 제어기 경로로 만든 저장 상태를 격리 환경에서 재현했다.

## 원인과 변경

`finishSafari`는 정상적으로 사파리를 완료하고 `screen: reward`, `rewards: []`, `mystery.stage: resolved`를 저장한다. 원본도 `safari-zone-encounter.ts`의 `leaveEncounterWithoutBattle(true)`로 추가 보상 없이 떠난다. 서버의 기존 `skipReward`로 다음 웨이브로 갈 수 있지만, 화면의 빈 보상 진행 버튼은 이벤트 목록에 사파리가 빠져 있어 표시되지 않았다.

사파리의 빈 보상에만 `onEmptyContinue`를 전달해 보상 화면 제목 옆에 ‘다음으로’를 표시한다. ‘보상 정보를 기다린다’는 문구 대신 사파리 완료/추가 보상 없음으로 안내한다. 요청 잠금·사용 중 비활성·오류 표시는 보상 화면의 기존 처리를 사용한다. 보상이 있는 화면이나 다른 이벤트의 선택 정책을 변경하지 않는다.

처음 시도한 기존 화면 하단 버튼 방식은 모바일에서 게임 메뉴에 가려 터치를 받지 못했다. 따라서 버튼을 보상 화면 내부 상단에 배치했고 실제 hit test와 터치로 검사했다. 기존 승인된 보상·정비 화면을 유지한다.

저장 마이그레이션이나 새 규칙 표시는 필요 없다. 이미 저장된 `reward/[]/safari-zone` 상태에서도 새 화면이 기존 서버 행동을 호출한다. 입장료 재청구, 포획·도감 등록 반복, 임의 보상 생성, 파티 초기화가 없다. 실제 사용자 저장에 적용되는 것은 사용자가 별도로 관리하는 Sites 배포 이후다.

## 검증

- `tests/rogue-safari-recovery.test.mjs`: 9개. 만원 파티 놓아주기/교체, 여유 파티 자동 합류, 미포획, 대화 켜짐/꺼짐, 마지막 포획 선택 직전과 빈 보상에서 실제 저장 codec 복구, 기존 완료 저장의 직접 진행. 잘못된 교체/중복 수락/중복 진행/빈 보상 새로고침 거부, 43→44, 파티 HP·도감·입장 후 돈·볼·다른 슬롯·탐험 보존.
- `tests/browser/safari-recovery/`: 실제 Page/게임/보상 컴포넌트와 CSS 및 실제 제어기/뷰를 로컬 API에 연결한다. 실제 계정·Sites를 호출하지 않는다. 외부 이미지만 대체한다.
- 수정 전 c292473 화면: 390×844에서 저장된 빈 보상 화면의 다음 버튼 부재와 reload 후 계속 막힘을 확인했다. `/tmp/safari-browser-before.log`.
- 수정 후: 390×844, 375×667, 844×390, 1280×850의 4크기 × 기존 저장/놓아주기/교체/자동 합류/미포획 5경로 = 20개. 마지막 포획 선택과 빈 보상에서 reload, 버튼 hit test, 모바일 tap·데스크톱 Enter, 44웨이브 도달, 보존·브라우저 오류0·가로 overflow0. `/tmp/safari-browser-final.log`, 스크린샷은 무시 경로 `.sites-runtime/tests/safari-recovery/`.

최종 전체 검사·타입·빌드 결과는 아래 확정 결과에 기록한다. 화면 파일에는 기존 린트 오류가 있어 전체 린트 통과를 주장하지 않는다. 앱98오류/18경고, 보상 컴포넌트1오류(기존 props 재할당)는 기준 버전과 동일한 rule/위치이며 신규 진단이 없다. 새 테스트·harness·타입 파일의 린트는 따로 검사한다.

실계정의 해당 원본 저장, 실제 휴대폰·모바일 Safari/Android, 자연 1~200 플레이와 운영 배포는 검증하지 않았다. Sites는 변경하지 않는다. 진행 중이던 지속 폼 융합 일반화는 사파리 긴급 수정 전에 이름 있는 Git stash로 보존했으며 아직 완료 기능으로 계산하지 않는다.
