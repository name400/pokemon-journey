# 판매상 빈 보상 화면 진행 복구

독립 자연 QA의23층 포켓몬 판매상 거절 후 진행 차단을 확인했다. 서버는
구매/거절을 정상 완료해 `screen: reward`, `rewards: []`로 저장했지만,
클라이언트의 다음 버튼은 이벤트 이름 목록에 의존했고 판매상이 빠져 있었다.

`classicCanContinueEmptyReward` 공통 조건으로 이름 목록을 제거했다.
보상 단계이고 선택지가 없으며 포획·진화·기술·성장·사파리 포획·전투 전
선택·NPC 대화·구매 확인이 대기하지 않을 때 다음 버튼을 표시한다.
서버 skipReward에도 같은 필수 선택 검증을 연결했다. 사파리는 기존
내장 다음 버튼을 사용해 중복 표시하지 않는다. 이미 막힌 저장도 새
버전 필드나 데이터 수정 없이 재접속해 진행할 수 있다.

검증:
- 신규4개: 실제 판매상 구매/거절 → 저장 codec → 재접속 →24층 전투,
  6마리 구매 후 교체 선택 보호, 대기 선택 검증과 이벤트 이름 독립성.
- 기존 salesman/fun/safari/recovery 포함 표준 집중19/19,
  Worker 신규4/4. `/tmp/astra-empty-reward-final.log`,
  `/tmp/astra-empty-reward-worker.log`.
- 브라우저8/8:375/1280 각각 구매 완료·거절 완료는 다음 버튼1개로24층,
  구매 확인·6마리 교체 대기는 다음 버튼 없이23층 유지.
  `/tmp/astra-empty-reward-browser.log`,
  `.sites-runtime/tests/empty-reward-continuation/results.json` 및 화면4장.

성장 대기열은 기존 dispatcher가 먼저 처리한다. 실재하지 않는 포켓몬의
합성 성장 항목을 제거하는 기존 복구 동작을 필수 선택 우회로 해석하지
않았다. 실제 기술 교체 항목·포획·진화·대화 선택은 보존/차단 검증했다.

운영 저장/Sites/원격 Git/커밋 쓰기는 없다. 모든 이벤트 조합이나 전체
전투 진행을 검증한 것은 아니며 전체 검사 결과는 부모 통합 기록을 따른다.

## 독립 배포 가능한 수정 검증

부모는816348d의 별도 임시 작업 트리에서 이 UI/game/helper와 신규fixture/test만 적용해 다른 진행 중 구현과 분리했다. 빈 보상·기존마자용·사파리검사17/17, 타입·production빌드 통과. `/tmp/salesman-isolated-{focus,type,build}.log`가 근거다. 원래 작업 트리의 다른 융합/도구/이미지 변경은 이 긴급 수정 커밋에 포함하지 않는다. Git 저장은 부모가 승인된 기존 브랜치에 수행하며 Sites 저장·배포는 사용자 담당이다.
