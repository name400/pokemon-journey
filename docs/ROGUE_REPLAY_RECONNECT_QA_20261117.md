# 포켓로그 재접속 연출 조사

2026-11-17 개발본에서 전투 화면은 `classicBattlePresentationKey`의 도전 ID·웨이브·턴·이벤트 내용으로 재생을 구분한다. 재생 완료 여부는 스킵·시간 초과·중단과 구분해 각 이벤트의 프레임 노출과 재생 종료를 확인하며, 모든 이벤트에 대한 증거가 있을 때만 세션 저장소에 기록한다. 이 기록은 아직 재생 억제에 사용하지 않는다. 사용자의 재생 완료와 게임 보상 지급은 서로 다른 경로다.

격리 Chromium과 로컬 fixture API에서 정상 등장 연출 후 새로고침 시 같은 연출이 재생되고, `window.open`으로 열린 탭에 원래 탭의 `sessionStorage` 완료 기록이 복사되는 것을 재확인했다. 움직임 줄이기나 백그라운드 때문에 보지 못한 경우 완료 기록은 남지 않고 이후 다시 재생됐다. 별도 더블 전투 fixture에서 첫 등장과 실제 엔진 명령으로 발생한 교체의 재생 도중 창을 열고 새로고침했을 때 완료 기록이 없고 연출이 다시 재생됐으며, fixture의 전투·파티·보상 저장은 변하지 않았다. 이 검사에서 창 복제는 `window.open`으로 모사했으며 브라우저의 모든 복제·복원 방식이나 실제 기기를 대표하지 않는다.

탭을 복제할 때 완료 기록까지 복사되므로 이를 그대로 읽어 억제하면 새 탭에서 보지 않은 사건을 누락할 수 있다. `window.opener`만으로는 opener가 없는 브라우저 복제·복구를 모두 구분할 수 없고, 완료가 불확실한 부분 기록도 임의 삭제할 수 없다. 따라서 안전한 탭 정체성 및 표시 완료를 입증하기 전까지 재접속 중복 억제는 비활성으로 남긴다. 격리 재생·완료 증거 단위 검사 28건이 통과했다. 원본 재생 영상과 모든 기기·다중 전투 조합 및 운영 저장은 미검증이다.

## 별도 다중 전투 상태창 표시 오류

탐험 다중 전투 상태창에서 빈 아군 슬롯을 제거한 뒤에도 제거 전 슬롯 수로 아군/상대 표제를 구분해, 첫 상대를 아군이라고 표시하는 문제를 격리 화면에서 재현했다. 표시할 포켓몬과 진영을 함께 묶은 뒤 빈 슬롯을 제거하도록 수정했다. 모바일 390×844·PC 1280×800에서 아군 빈 슬롯, 상대 빈 슬롯, 빈 슬롯 없는 경우와 상태창을 닫을 때 전투 명령이 발생하지 않는 것을 확인했다. 이 검사는 실제 전투 DTO에 빈 슬롯을 주입하고 외부 이미지를 대체한 화면 검사다. 단일 상태창은 승인 원본 코드와 같은 데이터의 네 크기 검사로 회귀 확인했다. 전투 엔진·저장·보상은 변경하지 않았다. Sites에는 배포하지 않았다.
