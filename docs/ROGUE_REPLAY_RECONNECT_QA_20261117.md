# 포켓로그 재접속 연출 조사

2026-11-17 개발본에서 전투 화면은 `classicBattlePresentationKey`의 도전 ID·웨이브·턴·이벤트 내용으로 재생을 구분한다. 재생 완료 여부는 스킵·시간 초과·중단과 구분해 각 이벤트의 프레임 노출과 재생 종료를 확인하며, 모든 이벤트에 대한 증거가 있을 때만 세션 저장소에 기록한다. 이 기록은 아직 재생 억제에 사용하지 않는다. 사용자의 재생 완료와 게임 보상 지급은 서로 다른 경로다.

격리 Chromium과 로컬 fixture API에서 정상 등장 연출 후 새로고침 시 같은 연출이 재생되고, `window.open`으로 열린 탭에 원래 탭의 `sessionStorage` 완료 기록이 복사되는 것을 재확인했다. 움직임 줄이기나 백그라운드 때문에 보지 못한 경우 완료 기록은 남지 않고 이후 다시 재생됐다. 별도 더블 전투 fixture에서 첫 등장과 실제 엔진 명령으로 발생한 교체의 재생 도중 창을 열고 새로고침했을 때 완료 기록이 없고 연출이 다시 재생됐으며, fixture의 전투·파티·보상 저장은 변하지 않았다. 이 검사에서 창 복제는 `window.open`으로 모사했으며 브라우저의 모든 복제·복원 방식이나 실제 기기를 대표하지 않는다.

탭을 복제할 때 완료 기록까지 복사되므로 이를 그대로 읽어 억제하면 새 탭에서 보지 않은 사건을 누락할 수 있다. `window.opener`만으로는 opener가 없는 브라우저 복제·복구를 모두 구분할 수 없고, 완료가 불확실한 부분 기록도 임의 삭제할 수 없다. 따라서 안전한 탭 정체성 및 표시 완료를 입증하기 전까지 재접속 중복 억제는 비활성으로 남긴다. 격리 재생·완료 증거 단위 검사 28건이 통과했다. 원본 재생 영상과 모든 기기·다중 전투 조합 및 운영 저장은 미검증이다.

후속 재검사: 격리 Chromium 단일 전투에서 등장 두 건이 새로고침 뒤 다시 재생되었고 `window.open` 탭에 시험 완료 기록이 복사됐다. 움직임 줄이기와 백그라운드 재생은 완료로 기록되지 않았으며 다시 접근하면 재생됐다. 이는 해당 브라우저 fixture의 결과이며 모든 탭 복제 방식이나 실기기 검증은 아니다. 중복 억제는 적용하지 않았다.

## 2026-11-18 재접속·연결 중단 재검사

현재 키는 도전 ID·웨이브·턴·이벤트 전체 JSON·결과를 합친 것으로, 서버가 이벤트별 영구 식별자나 표시 확인 상태를 저장하는 구조가 아니다. `PresentationReceipt`는 각 이벤트의 표시 프레임과 재생 완료를 모으고 전부 확인된 경우에만 `sessionStorage`에 진단용으로 기록한다. 타임아웃·취소·가림 등으로 무효화되면 억제 가능한 완료 기록을 만들지 않으며, 현재는 기록을 읽어 재생을 생략하는 경로가 없다. 화면 이펙트 처리와 게임 보상·저장은 별개다.

격리 Chromium에서 단일 첫 등장 두 이벤트가 새로고침 뒤 반복되고, `window.open`으로 연 탭에 시험 완료 기록이 복사되는 것을 재확인했다. 움직임 줄이기·백그라운드 후에는 미표시 연출이 이후 다시 재생됐다. 더블 첫 등장과 실제 교체 이벤트는 재생 중 새로고침한 뒤 다시 재생됐고 격리 저장은 그대로였다. 새 오프라인 검사에서는 등장 재생 도중 네트워크 차단으로 요청과 새로고침이 실패한 뒤 연결을 복구하면 중단된 등장 연출이 다시 재생되고 격리 저장이 유지됐다. 최초 검사 초안은 화면을 처음 열기 전 fixture 상태를 비교해 초기 조회의 정규화 차이에 실패했으며, 화면을 연 직후 상태를 기준으로 수정해 재실행했다. 완료 증거와 대화 순서의 단위 검사 6건도 통과했다.

`sessionStorage`를 그대로 사용하면 복제 탭에서 보지 못한 연출을 생략할 수 있다. 또 앞서 확인한 `pointer-events:none` 불투명 가림은 적중 검사로 식별하지 못하므로 완료 증거 자체도 실제 표시를 보장하지 않는다. 명시적인 사용자 확인을 받는 이벤트 이력, 복제·복원에서 충돌하지 않는 뷰어 식별과 이벤트별 안정 ID를 설계하고 가림·중단의 보수적 처리 및 구형 저장 호환을 검증하는 방안이 남는다. 이러한 방안은 아직 자동 중복 제거의 구현이나 검증이 아니다. 기존 기록을 신뢰해 재생을 억제하지 않았다. 실제 기기·운영 저장·브라우저의 모든 탭 복제 방식 및 구형 저장의 전수 복원은 검사하지 않았다.

## 표시 가림 추가 검사

화면 중앙만 확인하면 실제 이벤트 대상이 다른 요소에 가려져도 완료 기록이 남는 사례를 재현했다. 이벤트의 명시적 배우와 대상의 가시성과 여러 지점의 입력 적중을 추가로 확인해 불확실할 때 기록을 남기지 않도록 보수적으로 변경했다. 격리 API의 단일·더블 실제 명령에서 PC와 모바일 크기 각각 가림 여부와 저장 불변을 확인했다. 중단된 Z기술·교체와 전투 기록 스크롤 회귀도 통과했다.

다만 `pointer-events: none`인 불투명 덮개는 적중 검사에서 건너뛰므로 실제로 가렸어도 기록이 생길 수 있음을 별도로 재현했다. 표본 지점 검사도 모든 픽셀의 표시를 보장하지 않는다. 이 기록은 여전히 진단용이며 중복 재생 억제에 사용하지 않는다. 복제 탭 식별과 실제 표시 완료의 안전한 판별이 남아 있다.

승인 테라스탈 영상에서 결정과 왕관이 늦게 등장하는 순서를 확인해 기존 6.5초 전환의 표시 시점을 조정했다. 격리 단일 모바일 및 더블 명령에서 단계별 표시와 PP·저장 복원을 확인했다. 영상과 픽셀 단위 동일성 및 실기기는 미검증이다.

## 승인 UI 자산 무결성 확인

수신한 v52 원본 매니페스트의 SHA-256을 현재 게임 파일과 비교했다. 진화 배경 1개, 원본 매니페스트에 들어 있는 타입 아이콘 13개, 볼·회복 아이템 아이콘 4개가 모두 일치한다. 타입 아이콘은 공통 배틀의 타입 번호 매핑으로 연결되어 있다. 이 검사는 파일과 연결 확인이며 실제 화면의 위치·크기나 미수록 타입의 원본 일치 검증은 아니다. 추가 UI 변경이나 배포는 하지 않았다.

## 별도 다중 전투 상태창 표시 오류

탐험 다중 전투 상태창에서 빈 아군 슬롯을 제거한 뒤에도 제거 전 슬롯 수로 아군/상대 표제를 구분해, 첫 상대를 아군이라고 표시하는 문제를 격리 화면에서 재현했다. 표시할 포켓몬과 진영을 함께 묶은 뒤 빈 슬롯을 제거하도록 수정했다. 모바일 390×844·PC 1280×800에서 아군 빈 슬롯, 상대 빈 슬롯, 빈 슬롯 없는 경우와 상태창을 닫을 때 전투 명령이 발생하지 않는 것을 확인했다. 이 검사는 실제 전투 DTO에 빈 슬롯을 주입하고 외부 이미지를 대체한 화면 검사다. 단일 상태창은 승인 원본 코드와 같은 데이터의 네 크기 검사로 회귀 확인했다. 전투 엔진·저장·보상은 변경하지 않았다.
