# 토중몬 융합 진화와 추가 껍질몬

기준 `b0d661a`, 고정 원본 `/workspace/pokerogue-reference`의 `7c0881255af5cd51992e513ff93c2f71adbe40e0`. 이번 단위는 기존의 명시적 미지원 경로인 **융합 양쪽 역할의 토중몬 → 아이스크 + 껍질몬 생성**이다. 기존 207폼 목록의 숫자를 늘리는 폼 허용 작업은 아니다. 운영 데이터·Sites·원격 쓰기·커밋은 수행하지 않으며 부모가 통합한다.

## 원본 근거

- `src/field/pokemon.ts` 6284–6411: `evolve`에서 진화 전 `handleSpecialEvolutions` 호출. 토중몬이 주체든 융합 상대든 해당 쪽을 아이스크로 바꾼다. 추가 개체에는 기술·IV·성격·이로치·융합 상대 메타데이터를 복사하고, 같은 쪽을 껍질몬으로 진화시킨다. 새 주체 성별은 없음이다. 소유한 `PokemonHeldItemModifier`를 새 ID로 복제한다.
- `src/data/balance/pokemon-evolutions.ts` 231–233: 빈 파티 자리와 몬스터볼 수량 >0을 요구한다. 이 생성 함수는 볼을 차감하지 않는다. 빈 자리나 볼이 없어도 아이스크 진화 자체는 가능하다.
- `src/field/pokemon.ts` 1570–1593/2423–2427: 최대 HP1은 불가사의부적의 일반 또는 패시브 보유 여부로 결정한다. `hasAbility(..., false, true)`이므로 특성 억제로 기본 최대 HP가 증가하지 않는다. 주체 껍질몬이라도 융합 상대의 다른 특성을 쓰면 종 ID만으로 HP1을 강제하지 않는다.

## 구현

- `lib/rogue-evolution.mjs`: 기증자 토중몬의 진화 후보를 연결하고 주체 토중몬의 기존 차단을 제거했다. 껍질몬 직접 선택은 계속 불가능하다. 원본의 추가 생성 조건이 충족될 때만 새 개체를 만든다.
- 두 진화와 복제 도구를 임시 사본에서 계산·검증한 뒤 원래 run에 반영한다. 손상된 융합이나 임시 다이맥스 HP는 원본 파티 변경 없이 거부한다. 새 개체의 저장 ID·기증자 레코드·도구의 중첩 객체는 공유하지 않는다.
- 추가 개체는 진화 이전 기술과 융합 상대를 보존한다. 소유자별 modifier와 formItems를 새 소유 ID로 깊게 복사한다. 현재 상태 이상·랭크 변화·활성 테라·과거 전투 외형은 복사하지 않는다. 원래 기절한 개체는 기절 상태를 유지하고 새 개체는 별도로 생성된다.
- 기존 controller의 실제 진화 및 전투 재동기화 경로가 새 파티원을 네이티브 대기 파티에 추가한다. 공통 `rogue-classic-game.mjs`/`rogue-battle-engine.mjs`를 수정하지 않았다.
- 새 추가 개체에만 `rogueShedinjaHpRule: source-ability-v1`을 저장한다. `pokemon-config.mjs`가 이 명시적 규칙에서만 종 ID 단독 HP1 강제를 해제한다. 일반/패시브 불가사의부적은 계속 HP1이며 분리 후 주체 껍질몬의 특성·HP도 올바르게 복원한다. 표시 없는 기존 저장과 Adventure의 HP 계산은 유지한다. 기존 잘못된 HP를 추측해서 소급 변경하지 않는다.

2. 6마리 파티·일반 볼 부재에서 추가 생성 없음과 직접 껍질몬 선택 거부.

## 남은 범위

토중몬 융합 특수 진화 단위를 완료했다. 지가르데 외 자동 폼 전반, 다른 미지원 진화 조건과 모든 추가 개체 생성, 207폼 각각을 상대에 넣은 전수 조합은 이번 완료 범위가 아니다. 소스 새 개체의 모든 난수 소비·새 테라 타입 추첨까지 동일한 숫자 ID/RNG로 재현한다는 주장도 하지 않는다. 이미 검증한 로컬 UUID/메타데이터 표현을 사용한다. 새 UI/자산 변경은 없고 실계정·실기기·자연 200층·운영 배포 검사는 하지 않았다. 원본 Disabled 콘텐츠는 활성화하지 않았다.

최종 집중검사: 표준 **47/47**(2.72초, `/tmp/nincada-focus-final.log`), Worker 정책 **47/47**(3.59초, `/tmp/nincada-worker-final.log`), 소유 backend/test 네 파일 ESLint **오류0·경고0**(`/tmp/nincada-lint.log`), 소유 diff 공백검사 통과. 이 뒤 구현 코드는 변경하지 않았다. 전체 회귀·타입·production 빌드는 부모의 병렬 작업 통합 검사로 남긴다.
