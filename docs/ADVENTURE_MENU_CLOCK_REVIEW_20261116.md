# 메뉴·지도 시계 정지 검토

현재 메뉴와 지도는 브라우저의 `screen` 상태이며 서버가 열림·닫힘이나 탭 생존을 알지 못한다. 서버 시계는 `zaClockPauseStartedAt`과 `zaClockPausedMs`로 실내·지하·특정 전투 시간을 이미 누적하며, 일반 야생 전투 등은 흐르도록 구분한다. 각 저장 변경은 `worlds.revision` 조건부 갱신에 묶여 있고 이동 요청 및 포획 창도 리비전에 의존한다.

메뉴 정지는 아직 구현하지 않았다. 단순 플래그나 마지막 탭의 닫기 요청만으로 처리하면 비정상 종료 시 영구 정지되거나, 오래된 탭의 닫기·갱신이 다른 탭의 상태를 해제할 수 있다. 별도 정지 시간을 기존 실내·전투 누적치에 더하면 겹친 구간을 두 번 차감한다. 일반 저장 리비전을 갱신하는 심장박동을 무작정 추가하면 다른 탭의 정상 이동, 대기 중인 포획 창과 요청 복구에 충돌을 만들 수 있다. 현재 코드에는 서버 권위 탭 소유권·만료와 이 경계의 원자적 처리 경로가 없어 안전한 부분 적용 범위를 확인하지 못했다.

후속 구현은 최소한 서버 시각을 쓰는 만료 임대와 소유 토큰·세대, 오래된 갱신과 종료 요청 차단, 다른 탭이 실제 필드 행동을 시작할 때의 권위 규칙, 연결 손실 후 만료·재접속, 실내·전투 정지와 메뉴 정지의 합집합 계산을 함께 다뤄야 한다. 리비전 충돌·이동 복구·포획 창과 저장 원자성도 실제 D1과 브라우저 다중 탭에서 검증해야 한다. 시간 정지의 원작 적용 범위와 만료 지연은 별도 실기 확인 전 근사다. 기존 저장과 연속 플레이 검증 D1은 변경하지 않았다.

## 격리 계산 모델

`adventure-clock-lease-prototype.mjs`는 라이브 API와 클라이언트에서 사용하지 않는 순수 모델이다. 기존 시계 값을 한 시점에 읽어 정지 누적값을 잡고, 이후 실내·전투 정지와 유효 탭 임대의 시간 합집합을 계산한다. 실내·전투 판정은 기존 서버 함수와 공유한다. 소유자별 세대와 리비전으로 과거 종료·갱신을 거절하고, 임대가 만료되면 다시 열어야 한다. 실험 정책상 필드 행동은 모든 메뉴 임대를 해제하며 임대 시간 20초와 최대 8개는 임의의 시험값이다. 서로 다른 기기에서 어떤 탭이 필드 제어권을 얻는지, 백그라운드 탭의 자동 재획득을 어떻게 막는지는 실제 제품 정책과 클라이언트 구현에서 해결해야 한다.

순수 모델에서 두 탭의 겹침·종료·만료, 만료 후 재접속, 세대·리비전 충돌, 필드 행동, 실내·전투 겹침과 구형 저장 기준점 보존을 검사했다. 별도의 메모리 D1에서는 동일 리비전의 동시 쓰기 중 하나만 조건부 갱신되는 것을 확인했다. 실제 `worlds` 저장과 포획 창, 이동 복구, 새로고침·탭 종료·네트워크 장애 시 브라우저 동작은 연결하거나 검증하지 않았다. 모델의 리비전은 원자적 저장 자체가 아니며 실제 경로는 서버에서 검증하고 D1 트랜잭션·기존 리비전 규칙과 결합해야 한다. 안전 조건을 확인하기 전 활성화하지 않는다.

## 격리 `worlds` 저장 어댑터

`adventure-clock-world-prototype.mjs`를 API에 연결하지 않은 시험 어댑터로 추가했다. 실제와 같은 열을 가진 별도 메모리 D1의 `worlds` 행을 사용해 임대 상태와 리비전을 조건부로 함께 갱신한다. 포획 창과 위치 저장의 리비전이 이전 행과 일치할 때만 새 리비전으로 옮기고, 불일치한 과거 위치와 포켓몬·진행·미지 필드는 보존한다. 정상 필드 행동은 모든 메뉴 임대를 취소하며, 실내 또는 전투 상태 전환은 이전 정지 상태를 전환 시각까지 정산한 다음 적용한다. 기존 시간 필드의 직접 변경과 인지하지 못한 월드 리비전 변경은 임의 변환하지 않고 거절한다.

동일 리비전의 동시 열기, 포획 창·위치 리비전 보존, 만료와 재열기, 오래된 요청, 실내와 일반 야생·트레이너 전투 경계를 격리 검사했다. 원래 `movementFence`는 시험 시계 리비전을 갱신하지 않았으므로, 버전과 현재 리비전이 일치하는 시험 상태에 한해 위치·포획 창과 함께 시계 리비전을 같은 SQL에서 올리도록 보완했다. 복구 펜스는 소유권이나 정지 시간을 바꾸지 않는다. 실제 API 경로를 격리 SQLite에서 호출해 포획 창·위치·시계 리비전과 지연된 이동 거절을 검사했다. 이 경로는 시험 상태를 생성하지 않으며 **메뉴 정지는 실제 API·화면에 아직 활성화되지 않았다.**

당시 일반 `commit`, 읽기 중 자동 저장되는 조우·메달, 조기 반환과 시간 조회는 같은 프로토콜로 연결되지 않았다. 정상 이동이 시험 시계 없이 저장되면 실험 어댑터는 불일치를 거절하므로 기능을 켤 수 없었다. 아래 절은 이후의 시험 연결과 남은 차단을 설명한다.

## 실제 라우트의 비활성 시험 연결

후속 작업에서 일반 `commit`, 읽기 중 야생 개체 초기화와 메달 정산, 휴식과 시간 조회를 시험 시계에 연결했다. 서버 전용 시험 스위치가 켜진 격리 환경에서만 작동하고, 기본 상태에서는 임대 API가 거절되며 기존 시계가 동작한다. 시험 API는 서버에서 탭별 토큰을 발급하고 요청한 탭에만 반환하며, 일반 월드 응답에서는 임대 상태를 제거한다. 모든 월드 갱신을 리비전으로 조건부 처리하고 필드 행동 시 소유권을 해제하는 실험 정책을 사용한다. 메뉴에서 허용할 작업 목록과 20초 만료는 아직 제품 정책으로 확정되지 않았다.

실제 라우트의 격리 SQLite 검사에서 읽기 중 야생 초기화·메달 지급, 수면, 트레이너 배틀의 시작과 재접속, 두 탭의 동시 열기·오래된 요청·만료, 포획 창과 이동 복구를 확인했다. 친구 교환 시 두 계정의 월드·시계 리비전과 소유권을 한 거래에 반영하는 시험 연결도 추가해 기존 교환 회귀와 함께 확인했다. 별도 격리 Miniflare D1과 Chromium 두 탭의 **합성 시험 페이지**에서는 서버 응답 유실 뒤 구 리비전 재시도 거절, 복구 펜스, 탭 종료 후 만료와 다른 탭의 재접속을 확인했다. 실제 게임 UI와 브라우저의 화면 열기·백그라운드·종료 처리는 연결하거나 검증하지 않았다.

실제 활성화는 보류한다. 게임 UI의 탭 포커스·자동 갱신과 화면 종료, 포획 창 및 모든 메뉴 동작의 정책을 결정하고 구현해야 한다. 또한 관리자와 다른 모드가 같은 `worlds` 리비전을 바꾸는 경로와의 충돌·복구, 여러 기기 및 브라우저 정지·재개를 검증해야 한다. 시험 게이트 외에는 새 임대 저장을 만들지 않으며 운영·연속 검증 D1은 사용하지 않았다.

## 관리자 경로의 비활성 시험 연결

관리자의 포켓몬 지급은 월드 리비전만 올렸으므로 시험 시계와 리비전이 어긋날 수 있었다. 시험 게이트가 켜진 경우 지급은 월드·시계 조건부 갱신과 포켓몬 지급·감사 기록을 한 배치로 묶고, 수정도 기존 조건부 갱신 전에 시계 상태를 전환한다. 관리 작업은 시험 정책상 메뉴 소유권을 해제한다. 게이트가 꺼진 기존 경로는 변경하지 않았다.

실제 관리자 함수를 격리 Miniflare D1에서 실행해 지급·수정·시계 리비전 및 소유권, 불일치 시 지급 거절과 구형 저장을 검사했다. 이 검사는 관리자 초기화·복원, 다른 엔진의 쓰기 및 실제 화면 다중 탭을 검증하지 않는다. 이 경로들과 브라우저 탭 수명주기 연결이 남아 있으므로 실제 기능은 여전히 비활성이다.
