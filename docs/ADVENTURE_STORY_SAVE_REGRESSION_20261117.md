# 스토리 분기·저장 격리 회귀 (2026-11-17)

기준 개발본 `33a47be4`와 이 검사에서 추가한 미션 38 동시 요청 회귀를 사용했다. 기존 사용자 저장과 이전 연속 검증 저장은 열거나 변경하지 않았다. SQLite 메모리 API는 시험 단계·위치·상대 상태를 설정하는 기존 픽스처이며 일부 전투에는 레벨 100 시험 개체와 HP·상태 조정이 들어간다. 정상 육성이나 전체 연속 클리어 검증이 아니다.

- 메모리 SQLite의 실제 탐험 API 검사 21건 통과: 미션 19 클레피의 직접·전투·포획창 세 경로, 볼 보류·가방 한도·미래 형식 보존, 미션 20 결정 보상·유령 및 미확인 기록, 미션 31 회의, 미션 37 실패·구형 전투·지가르데나이트, 미션 38 선물·선택 분기, 미션 40·41 병렬 진행과 신형/구형 시뮬레이터, 미션 42 도입·포획 및 완료 후 중복 방지의 선택된 사례다.
- Miniflare의 격리 D1에서 실제 API의 미션 37 소유권·리비전·보상 복원과 미션 38 여섯 마리 파티·선물 중복 방지가 각각 통과했다. 미션 38 검사에 같은 리비전을 가진 두 요청을 동시에 보내는 경우를 추가해 200 하나와 409 하나, 선물 한 개, 기존 파티·보유 개체·재화 보존과 재접속 후 재요청 거절을 확인했다.
- 최초 D1 두 파일 병렬 실행에서 미션 37 테스트 프로세스가 상세 오류 없이 실패했으나 단독 및 `--test-concurrency=1` 순차 실행은 통과했다. 병렬 실패의 정확한 원인은 확인하지 못했다.

이번 사례에서 게임의 진행 차단이나 중복 보상 결함은 재현되지 않아 게임 코드는 바꾸지 않았다. 전체 스토리·모든 구형 저장·모든 보상, 실제 운영 D1, 물리 기기 및 정상 육성은 미검증이다. Sites 배포는 하지 않았다.

## 병렬 실패 재현과 추가 분기

미션 37·38 D1 테스트를 다시 병렬 실행하자 TAP에서 두 테스트 파일의 자식 프로세스가 모두 `SIGKILL`로 종료됐다. 같은 실행 전후 공유 cgroup의 `memory.events`는 `oom` 428→431, `oom_kill` 95→97로 증가했고 제한은 16GiB였다. 따라서 **이번 재현**은 메모리 한도에 의한 프로세스 종료와 일치한다. 이전 단일 실패 시점의 카운터는 기록되지 않아 그때의 원인을 확정하지는 않는다. 격리 테스트 외 공유 프로세스는 종료하지 않았다.

독립적인 경량 Miniflare 두 인스턴스를 병렬로 띄워 각 인스턴스의 리스닝 포트가 다르고, 각각 `DB`라는 바인딩에 기록한 값이 서로 섞이지 않음을 확인했다. 두 본 시험도 각각 자체 Miniflare와 D1을 생성하며 사용자 ID가 다르다. 이는 해당 구성의 포트·데이터 격리를 확인한 것이며 모든 환경에서 경쟁이 불가능하다는 증명은 아니다.

별도로 미션 37의 같은 전투 승리 명령을 동일 리비전으로 동시에 보내는 D1 회귀를 추가했다. 200과 409가 각각 하나였고 승리 진행·파티 소유권·보유함 수·저장 재조회가 유지됐다. 미션 37과 38 D1 검사를 `--test-concurrency=1`로 실행해 둘 다 통과했다. 원래 실패한 병렬 실행을 통과했다고 표시하지 않는다.

미션 21·23·24·26·27·35·36과 의뢰 63·67·72·74, 구형 미션 27~29 및 32~34의 분기·보상·재접속·이전 기록에 관한 격리 SQLite API 검사 15건도 통과했다. 일부 테스트는 100레벨 개체 또는 전투 상태 조작을 사용하므로 자연 플레이 완수 검사가 아니다. 이번 사례에서 수정할 게임 결함은 재현되지 않았다.
