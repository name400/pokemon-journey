# 포자 특성 일반 처리 조사 — 2026-11-18

세 기술에만 다른 발동 확률을 적용하는 미커밋 실험은 사용자 지시에 따라 해당 코드·전용 테스트·실험 기록만 제거했다. 현재 게임은 기존 시뮬레이터의 포자 판정을 사용한다. 포자 차이는 해결되지 않았다.

고정 원본 `7c0881255af5cd51992e513ff93c2f71adbe40e0`의 [포자 특성](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/data/abilities/ab-attrs.ts#L846)은 먼저 첫 상태를 무작위로 고르고, 접촉·기존 상태와 10% 판정을 거친 뒤 그 상태의 적용 가능성을 확인한다. 성공 시 세 상태 중 다시 뽑아 적용을 시도한다. 이전 설명의 적용 가능성 검사와 확률 판정 순서는 잘못되어 바로잡았다. 10%를 각 상태마다 따로 판정하지 않는다. 타입·특성·아군·필드의 상태 면역은 [상태 적용 가능성 확인](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/field/pokemon.ts#L4622)과 최종 적용 모두에 관여하므로 실제 상태이상 확률을 언제나 10%로 단정할 수 없다.

원본의 [대상별 후속 효과](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/phases/move-effect-phase.ts#L535)는 대타 여부에 따라 방어 특성을 호출하고, 다단 공격은 후속 타격을 별도 단계로 진행한다. 잠듦 등은 [남은 타격을 중단](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/field/pokemon.ts#L4760)한다. 실제 원본 런타임 실행이나 난수 생성기 일치는 확인하지 않았다.

격리 시뮬레이터에서 실험 제거 후 몸통박치기·물기·더블 몸통박치기는 모두 기존 `random(100)` 한 번을 사용했다. 세 번 맞는 연속뺨치기는 기존 판정을 세 번 호출했으며 강제 잠듦이면 첫 타격 후 중단했다. 이는 기존 엔진 동작 확인이지 원본 완전 일치 검증이 아니다.

사전 검사의 문제도 격리 전투에서 재현했다. 마비에 대해 `runStatusImmunity`는 유연 및 미스트필드에서 모두 허용을 반환했지만 실제 `SetStatus` 이벤트는 거부했다. 해당 이벤트를 시험 호출하면 각각 면역 또는 필드 로그가 추가됐다. 그러므로 타입 면역 조회만으로는 부족하고 실제 `SetStatus`를 그대로 호출하는 것은 부작용 없는 검사도 아니다. 패시브·상태 전달·필드·도구·억제와 대상별/다단 순서를 보존할 수 있는 명시적 순수 판정 또는 완전하게 격리된 시뮬레이션이 필요하다. 아직 검증되지 않아 일반 포자 규칙은 연결하지 않았다.

후속 재현: 격리 전투에서 몸통박치기와 물기의 실제 명중 직후 기존 엔진의 단일 0–99 난수에 20을 주면 마비가 발생한다. 고정 원본의 독립적인 10% 판정과 다른 구조다. 비접촉 기술은 기존 포자 콜백에 도달하지만 콜백 내부에서 난수를 소비하지 않고, 유연·미스트필드에서 타입 면역 조회만 허용되어도 실제 마비는 거부되는 점을 각각 확인했다. 앞서 비접촉에서 콜백 자체가 발동하지 않는다고 적은 설명은 잘못되어 정정했다. 이는 재현 검사이지 수정 완료 검사가 아니다. 포자 관찰 초기 검사 5건과 치유의마음·탈피 기존 회귀 33건이 통과했다. 포자 처리 변경은 안전한 범위가 확인되지 않아 적용하지 않았다.
