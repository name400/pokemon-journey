# 필드 포획의 볼 선택

도시·야생 구역 고정 개체뿐 아니라 구역 2·3과 하수도의 움직이는 개체 및 기존 우두머리 조준에서도 보유 볼을 선택할 수 있다. 몬스터볼은 지갑, 일반 특수 볼은 모험 월드, 희귀 볼은 기존 가방 또는 구형 월드 보관 수량에서 확인한다. 가방 희귀 볼을 먼저 사용하며 재고와 리비전은 기존 원자적 저장에서 검증한다. 볼 ID를 생략한 구형 요청은 몬스터볼을 사용한다.

기존 Z-A 포획 계산을 재사용해 퀵볼·타이머볼의 기술 사용 횟수, 수역 루어볼, 희귀 볼 조건, 밤·동굴과 속성, 마스터볼 및 프렌드볼 친밀도를 반영한다. 도시·고정 개체는 미발견 여부가 구현되어 있지 않아 미발견·뒤쪽 보너스를 주지 않는다. 일부 구역의 기존 조준은 이전 감지 조건을 그대로 사용하며, 동굴 여부는 기존 2D 하수도·터널·배수로 기준이다. 볼 효과와 실제 실시간 감지의 정확한 동등성은 보장하지 않는다. [볼 안내](https://allthings.how/pokemon-legends-z-a-poke-balls-and-how-to-get-every-type-of-it/)와 [퀵볼·타이머볼 설명](https://rotomlabs.net/guide/legends-z-a-capture-mechanics)을 참고했다.

격리 SQLite API에서 기본 볼 없음, 마스터볼 확정 포획, 희귀 볼 저장소 우선순위·프렌드볼 친밀도, 물가 루어볼 보정, 퀵볼 조준, 이로치·실패·재접속·중복 요청을 대표 검사했다. 희귀 볼의 개별 조건은 기존 단위 검사도 실행했다. PC·모바일 Chromium에서는 모의 API로 도시와 이동 개체의 볼 선택, 기본 볼이 없을 때의 대체 선택, 재접속을 확인했다. 실제 운영 D1·기기는 확인하지 않았다. 이동 처리와 충돌은 변경하지 않았다.
