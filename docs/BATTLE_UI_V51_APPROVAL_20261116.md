# 배틀 UI v51 승인 범위와 전달 상태

사용자는 적 포켓몬을 약간 내려 지면에 붙은 느낌을 주고 그림자를 조정한 최종 시안을 추가 검토 없이 통과하도록 승인했다. 승인된 배틀 UI와 실제로 보여주고 통과한 연출은 시각 표현을 두 모드에서 공유하되 포켓로그와 탐험모험의 규칙은 독립 유지한다. 별도로 보여준 다이맥스·테라스탈·Z기술 연출은 아직 승인되지 않았다. Sites 배포는 금지다.

제공된 최종 시안의 Library 기록은 확인했으나 현재 작업 환경에 파일을 가져오는 과정에서 다운로드가 실패했고 내용 읽기 연결도 종료됐다. 시안의 실제 화면과 코드를 확인하지 못했으므로 시각 변경은 적용하지 않았다. 파일에 접근할 수 있게 되면 승인된 버전과 구성 요소를 직접 비교해 구현하고 저장·모드별 동작을 검증한다.

후속 확인: 승인된 파일 기록은 `index(4).html`, 14,784,273바이트로 확인됐지만, Library 준비 결과는 작업 공간에 직접 복사된 파일이 아니라 다운로드 전송을 반환했다. 공식 전송 도우미 실행 결과 `download failed`였고, 별도 내용 읽기는 `Transport closed`로 실패했다. 파일 바이트와 시안 화면을 확인하지 못했으므로 구현하지 않았다. 접근 대안은 Library 읽기·전송 연결이 복구된 환경에서 같은 승인 파일을 전달받거나, 별도 시안 작업 환경이 원본을 공유 작업 공간에 직접 제공하는 것이다. 그 후 파일을 직접 확인하고 승인된 화면만 반영해야 한다. 사용자의 시안 승인 상태는 유지했고 구현이나 Sites 배포는 하지 않았다.

## v52 규격 부분 적용

전달된 v52 규격 가운데 단일 배틀의 아군 HP 수치를 실제 전투 상태에서 받아 HP 게이지 안에 표시하는 부분만 탐험·모험과 포켓로그 클래식 공통 컴포넌트에 연결했다. 다른 대전의 표시와 저장·전투 명령은 변경하지 않는다. 다중 배틀의 HP 표시는 기존 방식이다. 16:9 화면 전체, 스프라이트 실루엣·그림자, HUD 좌표, 명령·기술·볼 창과 터치 영역은 아직 v52로 구현하지 않았고 전체 시안이 반영된 상태가 아니다. 미승인 신규 변신 연출은 추가하지 않았다.

공통 컴포넌트 서버 렌더 검사와 타입 검사는 통과했다. Chromium의 모바일 크기 스크린샷 시도는 브라우저 프로세스가 종료되지 않아 결과를 얻지 못했다. 이는 실제 게임 화면이나 모바일 조작 검증이 아니며, 브라우저·모바일 검증이 남아 있다. 최초 Library 원본은 여전히 읽지 못했으며 이후 별도 경량본이 전달되면 시각 세부를 대조해야 한다.

## v52 단일 배틀 후속 적용

이미지 없는 경량 ZIP은 Library 기록과 크기 18,302바이트까지 확인했으나 전송 도우미에서 `download failed`가 발생했고, 내용 읽기는 ZIP을 해석하지 못했다. 따라서 파일을 직접 대조한 결과가 아니다. 전달된 텍스트 규격에 따라 두 대상 모드의 단일 전투에 16:9 장면, 포켓몬의 근사 좌표와 그림자, HUD 근사 위치, 싸운다·포켓몬·가방·도망 명령 및 볼 선택·상태 확인, 세로 기술 목록을 연결했다. 볼·가방·도망은 각 모드가 제공하는 기존 콜백과 포획 가능 여부를 사용하고 없는 행동은 비활성화한다. 기술 효과 좌표도 단일 전투의 변경된 위치를 따른다. 다중 전투는 기존 배치를 유지한다.

현재 명령·기술·볼·상태 창은 아직 장면 위의 v52 지정 좌표에 완전히 겹쳐 배치되지 않는다. 이미지 알파 경계를 이용한 단일 전투 실루엣 정렬, 종별 크기, 전체 360×202.5 스케일과 가로 세로 화면별 좌표, 미승인 연출, 실제 브라우저·터치 검증은 미완료다. HUD가 잘리지 않도록 아군 HUD의 세로 위치는 규격의 근사치다. 이미 제공된 효과 배율은 기존 엔진 표시를 그대로 사용한다. 새 다이맥스·테라스탈·Z 연출은 추가하지 않았다.

타입 검사와 배틀 렌더·진입 검사 4건, 명령·포획 불가 버튼 렌더 검사는 통과했다. Chromium 모바일 크기 정적 화면 시도는 프로세스 시간 초과로 결과를 얻지 못했으며, 실제 게임 조작이나 모바일 기기 검증이 아니다. Sites는 배포하지 않았다.

## 단일 배틀 접지와 명령 창 위치 보완

불투명 픽셀을 읽을 수 있는 스프라이트는 이미지의 좌우 중심과 최하단을 계산해 단일 배틀의 지정 접지점에 맞춘다. 읽을 수 없는 외부 이미지나 애니메이션은 비율에 근거한 기존 근사치를 사용하며, 애니메이션 이미지는 첫 프레임만 측정할 수 있다. 그림자도 계산한 접지점에 맞춘다. 브라우저 크기 변경과 이미지 로드 시 다시 계산한다.

단일 전투 명령·볼·상태 버튼은 헤더나 도구 행의 높이를 가정하지 않고 장면과 명령 영역의 위치를 측정해 장면 위에 배치한다. 버튼은 각각 최소 44px 높이를 유지하며 작은 장면에서는 지정 좌표보다 위로 이동한다. 기술·볼의 실제 선택 화면과 상세 상태 화면은 여전히 장면 아래에 있으며 v52 지정 좌표로 완성된 것이 아니다. 긴 이름은 영역을 넘지 않도록 생략 부호로 표시하며 화면 판독기에는 원래 텍스트가 남는다. 포켓로그·탐험의 전투 상태와 명령 자체는 변경하지 않는다.

별도 쓰기 가능한 브라우저 프로필·캐시와 단일 프로세스 설정으로 간단한 페이지도 다시 시도했으나 Chromium이 제한 시간 안에 화면을 만들지 못했다. 로그에는 시스템 D-Bus 연결 실패와 단일 프로세스의 프록시 해석기 오류가 있었으나 직접 원인으로 확정하지 못했다. 따라서 실제 브라우저의 위치·터치·문자·HP 잘림과 애니메이션 재생은 여전히 미검증이다. 서버 렌더·배틀 진입 검사 및 작은 장면에서의 명령 위치 계산 검사를 수행했다. 운영·실기·Sites 병합본 검증이나 배포는 하지 않았다.

## 기술·볼·상태 선택창의 경기장 배치

v52 단일 전투에서 기술 목록과 볼 선택 및 상태창을 측정한 경기장 위에 배치했다. 기술 이름·타입·PP와 기존 엔진의 상성 문구를 사용하며, 볼 수량과 선택 가능 여부, 확인 및 실제 포획 명령은 기존 모드별 경로를 사용한다. 가용 공간이 부족하면 선택창을 스크롤하고 각 기술 설명과 볼 버튼의 터치 높이를 44px 이상으로 유지한다. 포켓로그에서 경기장과 명령 영역의 너비·위치가 다른 경우에도 경기장 좌표를 명령 영역 기준으로 변환한다. 다중 전투와 게임 데이터는 변경하지 않았다.

대체 검사에서 상성 배율 0·0.25·0.5·1·2·4, PP 0의 선택 불가, 일반·좁은 경기장의 계산 범위, 배틀 진입 및 전략 명령을 확인했다. 이전에 기록한 Chromium 실행 차단 상태에서 실제 브라우저·모바일의 스크롤, 명령 터치, 겹침·글자 잘림 및 두 모드 전체 시각 결과는 여전히 미검증이다. 44px보다 작은 영역에서는 터치 영역을 물리적으로 경기장 내부에 모두 수용할 수 없다. Library 경량 시안의 실제 바이트는 확보하지 못했으므로 시안과의 시각 일치도 확정하지 않는다. 기존 배포 실패 기록은 유지했고 Sites는 배포하지 않았다.

## 선택창 스크롤 축소

단일 전투 기술창은 보통 크기에서 네 기술을 각 44px 높이로 표시하고, 경기장이 작으면 두 개 또는 한 개씩 페이지를 나눈다. 볼도 보유 목록을 순서대로 두 개씩 페이지를 나눠 선택한다. 선택·확인·소모는 기존 엔진 명령을 사용하며 모든 목록 항목에 접근할 수 있다. 긴 기술명은 짧은 행에서 말줄임 처리하고 전체 이름과 상세 설명은 접근성 이름과 설명 버튼에 남긴다. 포켓로그 단일 v52 화면에서는 가로 모바일의 종전 1450px 강제 뷰포트를 적용하지 않아, 명령·선택 버튼이 축소된 가상 좌표의 44px에 묶이지 않게 했다. 기존 다중 배틀의 뷰포트 처리는 유지한다.

이 변경은 **선택창 내부의 스크롤을 줄인 것**이며 전체 배틀 화면이 모든 기기에서 한 화면에 들어간다는 검증이나 보장은 아니다. 창의 여유 공간이 44px 터치 영역 자체보다 작거나 긴 상태 텍스트·설명 팝업이 있는 경우의 배치는 실기 검증이 필요하다. 브라우저 실행이 앞서 기록된 상태로 막혀 있어 렌더·페이지 계산 검사는 실제 터치·잘림·승인 시안 일치 검증이 아니다. 원본 시안 바이트와 승인된 개별 연출 영상도 이 환경에서 직접 비교하지 못했다. 기존 전투 연출과 모드별 명령·저장, 배포 실패 기록은 유지하며 Sites에는 배포하지 않았다.

## 탐험 직접 진화와 배틀 이벤트 연결

탐험·모험의 직접 진화는 실제 `evolve` 성공 응답에서 동일 `boxId`의 진화 전후와 새 리비전, 서버의 진화 이벤트를 모두 확인한 경우에만 관리 화면 안에 결과를 표시한다. 결과 확인 전에는 진화로 생긴 기술 선택창이 앞서 나오지 않는다. 서버 저장·보상·기술은 결과 확인과 무관하게 기존대로 확정되며, 새로고침이나 오래된 응답은 결과 장면을 추측해 재생하지 않는다. 결과 화면의 두 스프라이트와 짧은 밝기 변화는 기존 방식에 맞춘 근사 연출이며, 전달받지 못한 승인 영상과 동일하다고 검증한 것은 아니다. 화면이 응답 도착 전에 닫혔을 때는 결과를 강제로 다시 열지 않는다.

격리 API의 실제 직접 진화 응답을 확인해 같은 개체의 전후 상태가 전달됨을 검사했다. 별도의 실제 메가진화 전투 명령은 해당 개체의 폼 이벤트가 발생하고, 이벤트 전 기본 모습·이벤트 후 메가 모습으로 재생 상태가 변경되는지 확인했다. 교체·기술 재생과 취소, 움직임 줄이기는 기존 대표 검사를 실행했다. 다이맥스·테라스탈·Z 신규 영상을 추가하거나 승인 처리하지 않았다. 이전 Chromium 실행 장애로 실제 게임 화면·모바일 터치와 한 화면 여부는 여전히 미검증이며 기존 실패 기록과 Sites 미배포 상태를 유지한다.

## 교체·기술·진화·부화 연결과 재접속

탐험 단일 전투의 실제 기술 명령 후 GET 응답에도 직전 턴의 `events`가 남는 것을 격리 API에서 확인했다. 기존 클라이언트는 다중 전투만 재조회 이벤트를 비워 단일 전투 재접속에서 지나간 기술·교체·폼 연출을 다시 재생할 수 있었다. 이제 클라이언트의 GET 복원에만 단일·다중 전투의 이벤트를 비우고, 서버가 확정한 팀·HP·폼·차례와 새 POST 응답의 이벤트는 그대로 둔다. 저장이나 전투 판정은 변경하지 않는다.

포켓로그는 웨이브 종료 부화 결과를 `pendingHatches`에서 표시하고 개별 확인으로 제거한다. 격리 저장에서 실제 부화 결과가 화면용 상태에 전달되고, 재조회 뒤에도 남으며, 확인 시 해당 결과가 사라지는 경로를 검사했다. 탐험·모험에는 같은 알 부화 엔진 경로를 확인하지 못했으므로 새 부화 시스템을 만들지 않았다. 교체·기술·메가 이벤트와 진화 결과의 기존 대표 검사도 실행했다.

모션 원본 영상을 직접 받지 못해 승인 시안과 화면이 일치하는지는 확인하지 못했다. 실제 브라우저·모바일 화면, 터치, 한 화면 여부와 Sites 병합본은 미검증이며, 기존 실패 기록을 유지하고 배포하지 않았다.

## 교체 진입 연출 시점 보정

공통 배틀 재생에서 교체 이벤트 직후 이전 화면의 DOM을 찾아 새 포켓몬 진입 연출을 놓칠 수 있었다. 이벤트의 새 개체가 화면 상태에 반영된 뒤 기존 진입 애니메이션을 한 번 실행하도록 연결했다. 실제 전투 이벤트의 교체 전후 상태와 위치를 대표 검사했으며 전투 규칙이나 저장은 변경하지 않았다. 브라우저 렌더와 원본 승인 영상 대조는 아직 검증하지 못했다.

## 좁은 화면 기술 번호 입력

기술을 페이지로 나누는 단일 배틀에서 숫자키가 현재 보이지 않는 다른 페이지의 기술까지 선택할 수 있었다. 화면에 인쇄된 번호가 현재 페이지에 있는 경우에만 선택하도록 수정했다. 포켓로그와 탐험의 공통 표시 계층에서만 처리하며 명령의 서버 판정과 저장은 유지한다. 페이지별 번호 경계를 코드 검사했으며 실제 브라우저와 모바일 입력 검증은 하지 못했다.

숫자키가 일반 기술 객체를 그대로 사용해 화면에 표시된 특수 변화 기술의 대상이나 사용 불가 상태와 다르게 동작할 수 있는 문제도 수정했다. 포인터와 숫자키가 같은 표시용 기술을 사용하며, 기존 모드별 서버 명령·변화 규칙은 유지한다. 대상 변경과 사용 불가 상태의 코드 검사가 통과했다. 미승인 변신 영상은 추가하지 않았고 실제 브라우저·모바일과 승인 영상 대조는 여전히 미검증이다.

## 탐험 전투 시작 등장

실제 탐험 단일 전투 생성과 API 응답은 양측의 교체 등장 이벤트를 제공하지만 공통 화면은 탐험 모드에서 이벤트 재생 전부터 두 개체를 표시했다. 승인된 배틀 화면에서도 초기 등장만 해당 이벤트 순서에 맞춰 표시하도록 연결했다. 포켓로그의 기존 등장 처리와 별개로 탐험의 기절 표시 정규화는 변경하지 않는다. 이벤트가 없는 복원, 중간 교체, 메가링·동료 메가진화와 기존 저장을 대표 검사했다. 서버 렌더 및 이벤트 상태 검사는 실제 브라우저 애니메이션이나 승인 영상과의 시각 일치를 뜻하지 않는다. 모바일·Sites 병합본은 미검증이며 배포하지 않았다.

## 포켓로그 단일·더블 이벤트

실제 포켓로그 더블 전투에서 지진이 아군에게 피해를 주어도 공통 이벤트가 같은 편이라는 이유로 피격 신호를 빠뜨렸다. 공격자 자신과 다른 개체에 가한 직접 피해는 편에 상관없이 피격 신호를 내도록 수정했다. 반동 등 원인이 명시된 피해와 공격자 자신의 피해는 직접 피격으로 취급하지 않으며 전투 수치·규칙·저장은 변경하지 않는다.

레벨 100 격리 개체를 사용한 실제 단일 교체·기술과 더블 등장·교체·광역 공격, 전투 직렬화 후 상태·이벤트 순서를 검사했다. 서버가 저장한 최근 이벤트는 재접속 때 그대로 반환되므로 완료된 연출도 다시 재생될 수 있다. 미확인 대사와 재생 전 이벤트를 보존해야 하므로 이를 일괄 삭제하지 않았다. 실제 브라우저·모바일 및 원본 승인 영상 대조, Sites 병합본 검증은 하지 않았다.

## 재접속 완료 표식 검토와 포획 방향

포켓로그의 `presentedBattleKey`는 화면 메모리에만 있고 새로고침하면 사라진다. 현재 완료 콜백은 모든 이벤트가 보인 경우뿐 아니라 재생 시간 제한, 움직임 줄이기, 애니메이션 비활성 등으로 생략되거나 감시 타이머가 끝난 경우에도 호출된다. 이 콜백을 저장된 확인 증거로 그대로 사용하면 미확인 이벤트를 건너뛸 수 있다. 안전한 중복 방지에는 이벤트 전체가 표시된 사실을 생략·중단·숨겨진 탭과 구분한 완료 확인, 전투·이벤트별 식별자, 기기나 탭별 확인 범위와 대사 순서가 필요하다. 이를 검증하기 전 재접속 연출 반복은 보류하며 기존 이벤트·대사는 지우지 않는다.

별도로 포켓로그 실제 포획 이벤트의 `side`와 `boxId`는 포획 대상인 상대를 가리키는데, 화면이 이를 볼의 출발 위치로도 해석해 상대 쪽에서 볼이 출발했다. 공통 화면에서 포획 이벤트는 대상의 반대편에 살아 있는 출전 개체를 출발점으로 찾도록 수정했다. 상대의 실제 대상 식별자는 유지하며 구형 이벤트에도 적용한다. 단일·더블의 실제 포획 성공과 실패, 직렬화된 이벤트 및 첫 슬롯이 쓰러진 경우를 대표 검사했다. 포획 판정·볼 소비·서버 저장은 변경하지 않았다. 실제 브라우저·모바일 렌더와 승인 영상 대조는 미검증이며 Sites에는 배포하지 않았다.

## 축소 화면 터치 영역 보정

포켓로그 단일 전투의 작은 세로 화면과 짧은 가로 화면에서 배틀 화면을 88%로 축소하면서 명령·기술·설명 버튼의 실제 터치 높이가 44px보다 작아졌다. 이 두 구간에서 해당 버튼의 원래 크기를 50px로 지정해 축소 후 44px을 확보했다. 기존 명령과 두 모드의 전투 데이터는 변경하지 않는다.

격리 Chromium의 320×568, 390×844, 844×390에서 명령 여섯 개와 기술·설명 네 쌍의 화면 좌표, 네 기술 동시 표시, 페이지 스크롤 부재, 설명 열기·닫기와 메가 선택 후 네 번째 기술의 실제 테스트 API 명령을 확인했다. 같은 모의 환경의 레벨 100 포켓몬 및 대체 스프라이트를 사용했으며 실제 기기·실제 스프라이트·승인 원본 영상과의 시각 일치, Sites 병합본 및 운영은 미검증이다. 이 변경은 아이콘 전달 장애나 재접속 미확인 이벤트 문제를 해결하지 않는다.

## 탐험 전투 팝업과 좁은 화면

탐험의 공통 전투 화면이 필드 밑에 렌더링되어 320×568·390×844·844×390 및 1280×800 격리 화면에서 전투 명령에 닿으려면 페이지를 스크롤해야 했다. 필드 컴포넌트를 유지한 상태에서 전투를 별도 팝업으로 표시하고 배경 페이지의 스크롤을 잠갔다. 팝업의 탭 포커스를 내부에 유지하고 별도 네이티브 대화창은 방해하지 않으며, 전투 결과를 확인해 닫으면 기존 필드와 스크롤을 복원한다. 좁은 가로 화면은 경기장과 명령을 나란히 두는 적응형 배치다. 320px 세로와 844px 가로에서는 네 기술이 한 번에 표시된다. 긴 파티·가방 등 모든 패널과 모든 화면 크기의 스크롤 없는 배치는 아직 검증하지 않았다.

격리 Chromium에서 위 네 화면의 명령·상태·볼·기술 경계, 네 기술, 포커스, 별도 네이티브 대화창 및 실제 전투 엔진에 연결한 모의 API 명령을 검사했다. 별도 승리 결과 확인으로 팝업을 닫고 필드 좌표와 페이지 스크롤 복원을 확인했다. 미션 35 다중 전투와 포켓로그의 작은 화면 명령 회귀도 검사했다. 다중 전투 검사는 기존에 생략됐던 `싸운다` 선택을 현재 화면 흐름에 맞게 추가했다. 외부 이미지는 대체했으며 사용자 저장·운영 D1·실제 기기·원본 승인 영상·Sites 병합본은 검사하지 않았다. 첫 격리 Vite 서버는 종료 코드 137로 중단돼 결과가 없었고, 별도 포트에서 검사를 완료했다. 재접속 연출 반복과 승인 아이콘 파일 전달은 미해결이다.

## 탐험 전투 파티·가방 긴 목록

여섯 마리와 여러 회복 도구가 있는 격리 저장에서 파티와 가방이 팝업 높이를 크게 넘어 스크롤이 필요했다. 탐험 단일 전투에 파티 네 마리씩 페이지를 나누고, 가방은 포켓몬을 먼저 고른 뒤 해당 대상에 쓸 수 있는 도구를 네 개씩 표시하도록 했다. HP·상태, 취소와 명령 복귀를 유지한다. 강제 교체는 취소할 수 없지만 기존 기권 확인은 선택할 수 있다. 선두·대기·기절 대상의 기존 서버 명령과 적용 조건을 사용하며 포켓로그·다중 전투 UI는 변경하지 않았다. 선두의 개체 식별자가 없는 합성 응답에서도 선두 도구 명령을 유지한다.

격리 Chromium에서 320×568·390×844·844×390·1280×800의 여섯 마리·다수 도구를 사용해 팝업 경계와 스크롤, HP 표시, 전체 페이지, 취소, 선두·대기 회복, 상태 치료제, 기절 대상 부활과 교체 요청을 검사했다. 강제 교체의 두 번째 페이지와 기권 확인 취소도 별도 검사했다. 1280×800에서는 별도의 일반 데스크톱 Chromium 마우스 입력도 확인했다. 브라우저의 도구 API는 요청을 기록하는 모의 응답이며 실제 격리 SQLite API의 회복·상태·부활·재접속 대표 검사 4건을 별도로 통과했다. 외부 이미지는 대체했다. 실기기·승인 원본 시안·운영 D1·Sites 병합본과 모든 크기, 탐험 다중 전투의 긴 목록은 미검증이다. 기존 원본 아이콘 전달 장애와 재접속 연출 보류는 그대로다.

첫 Vite 서버 및 별도 타입 검사 한 번은 종료 코드 137로 중단됐고 원인은 확정하지 않았다. 이후 별도 Vite와 제한된 Node 힙의 타입 검사는 통과했다. 이는 과거 배포 실패나 전체 검사 통과를 뜻하지 않는다.

## 탐험 다중 전투의 긴 파티·가방

더블 전투의 여섯 마리와 동료가 표시된 파티는 320×568 격리 화면에서 전투 팝업 높이를 초과했다. 단일 전투의 페이지형 파티·가방을 탐험 더블·삼중 전투에도 적용하고, 교체 확인 화면도 팝업 안에 맞췄다. 동료는 파티에서 교체 불가로 표시하고 가방의 회복·부활 대상에서 제외한다. 실제 플레이어의 출전·대기 슬롯과 기존 서버 명령을 유지한다.

격리 Chromium에서 더블·삼중 전투 각각 320×568·844×390·1280×800의 긴 목록, 페이지, 동료 제외, 대기 회복·부활 요청 및 교체 확인을 검사했다. 두 작은 화면의 강제 교체와 기권 확인 취소도 별도 검사했다. 브라우저는 실제 전투 시뮬레이터를 사용한 모의 API이며, 실제 격리 SQLite API의 소유권·회복·부활·재접속 관련 검사 5건과 단일 전투 4개 크기 회귀, 타입 검사가 통과했다. 외부 이미지는 대체했으며 실제 기기·승인 원본 시안·운영 데이터·Sites 병합본 및 전체 화면 크기는 확인하지 않았다. 초기 Vite 서버 두 번은 종료 코드 137로 중단됐고 원인은 확정되지 않았으며, 다른 포트에서 위 검사를 수행했다.

## 포켓로그 재접속 재생 추가 조사

격리 Chromium의 실제 클래식 배틀 화면과 테스트 저장에서 등장 `switch` 두 건이 새로고침 후 다시 표시됨을 재현했다. 움직임 줄이기로 두 건이 생략된 뒤 다시 보통 모드로 새로고침하면 두 건이 재생되는 것도 확인했다. 별도 재생 컨트롤러 검사에서 움직임 줄이기·애니메이션 비활성·재생 예산 0은 표시된 이벤트가 없어도 성공을 반환하며, 취소는 실패를 반환하고 재실행이 가능함을 확인했다. 트레이너 대사와 패배·승리 대기에는 현재 완료 콜백이 계속 필요하다.

이 완료 신호는 화면 표시 확인이 아니므로 저장하거나 그 값으로 연출을 숨기지 않았다. 안전한 수정에는 서버 응답의 각 이벤트를 구별하고 실제 화면 프레임 반영과 탭 가시성·중단·시간 제한을 따로 추적하는 확인 신호가 필요하다. 저장소를 새로고침에 사용하는 경우 탭 복제·다른 기기·계정 전환에서도 확인이 공유되지 않음을 보장해야 한다. 기존 서버 저장과 대사 큐는 변경하지 않았다. 조사 검사는 정상 재생 후 새로고침 및 움직임 줄이기 후 새로고침만 확인했으며 강제 시간 초과의 브라우저 재접속, 다중 탭·실기기·운영은 미검증이다.

## 재접속 화면 표시 증거의 제한적 기록

클래식 전투 재생에 별도의 화면 표시 증거를 추가했다. 각 이벤트의 전투 프레임이 포커스된 보이는 탭에서 두 프레임 이상 화면에 반영되고 해당 이벤트에 할당된 재생 시간이 생략·취소·남은 예산에 의한 추가 단축 없이 끝나야 그 이벤트를 확인 후보로 기록한다. 탭 전환, 장면 중심점의 감지 가능한 가림, 애니메이션 생략, 감시 타임아웃과 컴포넌트 중단은 전체 시도를 무효로 한다. 모든 이벤트가 확인된 경우에만 탭 세션에 진단용 기록을 남기며 기존 대사 대기 해제 신호와 게임 저장은 변경하지 않는다. 이 기록은 현재 읽거나 재생을 생략하는 데 사용하지 않는다.

격리 Chromium에서 두 등장 이벤트의 정상 기록, 새로고침 시 기록 후에도 기존 재생, 움직임 줄이기에서 기록하지 않음, 다른 탭으로 전환 중 기록하지 않음과 복귀 후 재생을 확인했다. 별도 컨트롤러 검사는 비활성·시간 예산 0·건너뛰기·취소와 정상 프레임 종료를 확인했다. 새 창을 부모에서 열면 브라우저가 `sessionStorage`를 복제함도 재현했으므로 이 기록을 그대로 재접속 생략 근거로 쓸 수 없다. 기록은 마지막 완전한 한 묶음만 보관하며 부분 이벤트의 재접속 복구는 구현하지 않았다. 시간 초과·중단의 실제 모바일, 브라우저 외부 창에 의한 가림, 운영과 Sites 병합본은 미검증이다. 기록을 이용해 중복을 억제하기 전 독립 탭 식별과 프레임 가림 등의 경계가 필요하다.

타입 검사는 Node 힙 1024MB에서 메모리 한도 오류로 중단됐고, 1536MB로 다시 실행해 통과했다. 이는 전체 테스트나 배포 검증 결과가 아니다.
