# 이동 요청별 시각 경로 상태

`createVisualMovementRequests`는 화면 예측용 요청 하나의 시작 상태, 리비전, 보낸 칸 수, 순서 있는 칸과 대기 중 추가 칸을 보유한다. 정상 응답은 `confirmedCloudPathPrefix`로 검증해 보낸 접두부와 나머지를 분리한다. 불일치·부분 이동·전투·조우·포획 또는 학습 대기는 전체 폐기한다. 취소 이후에는 이전 토큰의 늦은 응답을 무시하며, 요청과 추가 경로가 충돌·층 전환·위험 예측으로 완성되지 않으면 등록하지 않는다. 호출자는 추가 실패 시에도 표시 중인 경로의 안전성을 확인하고 필요하면 전체 폐기해야 한다.

이 모듈은 메모리에서만 동작하며 이동 요청·저장을 실행하지 않는다. **아직 실제 클라이언트나 그리기 큐에 연결되지 않았고 화면 지연 개선도 없다.** 무조건 `accept`가 기존 예측을 지우는 실제 응답 흐름에 연결하면서, 세대·사용자 전환과 부분 이동·이벤트·타임아웃에서 렌더 큐를 명시적으로 취소하도록 구현해야 한다. 격리 단위 검사만으로 실제 D1과 다른 탭의 정합성이나 화면 성능은 검증되지 않았다.


후속: [실제 요청·Canvas 순서 큐 연결](ADVENTURE_ORDERED_VISUAL_QUEUE_20261113.md)을 구현하고 같은 입력의 모의 브라우저 프레임 및 복구 회귀를 검사했다. 위 미연결 설명은 최초 모듈 도입 당시의 상태이며, 후속 문서의 구현 범위와 한계를 함께 확인한다.
