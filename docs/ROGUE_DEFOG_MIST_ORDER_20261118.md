# Defog target Mist order — 2026-11-18

Pinned source applies self-targeted post-hit effects before target effects. Defog's side cleanup removes target Mist, while its evasion change is a separate target effect: [move definition](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/data/moves/move.ts#L10167), [self before target](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/phases/move-effect-phase.ts#L535), [side-tag cleanup](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/data/moves/move.ts#L6456). A before-fix isolated battle reproduced native Defog removing Mist but leaving target evasion unchanged because its boost callback ran first.

New games carry `defogMistOrderRule: source-v1` into the battle. The per-use callback removes only the actual target side's Mist before the native boost attempt, preserving success if that removal is the sole effect. Protected or blocked moves do not execute the callback. The previous cleanup-success and fog handling remain compatible. Existing runs without the flag retain prior behavior.

Isolated tests cover singles and doubles, Mist-before-evasion log order, target versus ally side, Protect, Clear Body, Contrary, Substitute, Magic Bounce reflection, minimum evasion, combined Defog rules, actual move command, PP and encoded restore, old saves and unrelated state. Eight related test files passed 74 cases; the subsequent added combined-rule check passed in a 14-case Defog Mist suite. Browser, actual devices, every ability, called moves and all field combinations were not verified. No running server or user data was used.
