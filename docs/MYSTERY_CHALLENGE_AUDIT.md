# 미스터리 이벤트 챌린지 대조 메모

고정 원본의 `src/data/mystery-encounters/encounters`와 `mystery-encounter-requirements.ts`, 이 프로젝트의 `lib/rogue-mystery.mjs`를 비교한 작업 메모다. 아래는 확인한 범위이며 전체 이벤트·폼·난수 동등성 표가 아니다. `source-subset-v1` 챌린지에 한해 판정이 불명확한 저장은 임의 허용하지 않는다.

| Teleporting Hijinks 기계 조작 | `TypeRequirement`는 조건 충족 여부를 볼 때 기절한 개체를 제외하지만, 후보 조회 자체는 받은 파티에서 강철·전기 타입을 찾는다. 이 조건은 챌린지 출전 가능 여부를 확인하지 않는다. | 새 도전에서 검증된 기본 폼 파티는 생존 타입 조건을 확인한 뒤 전체 파티의 첫 강철·전기 타입을 선택한다. 원본 옵션의 일반 경로는 추첨 없이 첫 후보를 택한다. 기절 후보는 전투 승리 후 경험치를 받지 않는다. 기존 도전과 미검증 폼은 이전의 생존 후보 방식을 유지한다. |

검사에서 실제 계정의 전체 플레이나 원본 RNG 상태를 전수 재현한 것은 아니다. 원본에서 비활성인 이벤트는 활성화하지 않는다. 사용자는 직접 배포하겠다고 지시했다. 현재 Sites 필수 소스 헬퍼 부재로 최신 변경의 Sites 저장이 막혀 있다.

## 후속 원본 선택 순서 재검토

`mystery-encounter-option.ts`의 `meetsPrimaryRequirementAndPrimaryPokemonSelected` 일반 경로는 `qualified[0]`을 사용하며 지원 후보 중복을 제외하는 분기에서만 난수를 사용한다. 순간이동의 일반 후보는 첫 번째다. 바다 안내와 Fiery Fallout의 기존 저장 후보 난수 구현도 해당 옵션에 지원 후보 중복 분기가 적용되는지 다시 확인해야 하므로 원본과 같다고 단정하지 않는다. 기존 진행의 저장 후보와 RNG를 보존하면서 수정할 수 있는 별도 규칙 버전과 회귀 검증이 필요하다.

원본 옵션 빌더와 구현을 다시 대조했다. 바다 두 선택지와 화산 진정은 보조 후보 없이 기본 후보 조건만 정의하므로 일반 경로에서 첫 후보를 사용한다. 새 `source-subset-v2` 도전은 후보 난수를 소비하지 않고, 이전 v1의 추첨과 기존에 저장된 후보를 유지한다. 기절·금지 개체, 미확인 폼이 섞인 파티의 나머지 차이는 그대로 남는다.

원본 희귀 품종 매료와 두 훔치기 선택도 보조 후보 없는 기본 참가자 조건이므로 첫 적격 후보를 사용한다. v2 도전은 후보 난수를 소비하지 않으며, 이전 v1 도전의 선택·난수와 진행 중 저장 후보는 보존한다. 옵션 재평가 시점과 불명확한 챌린지·폼은 완전한 원본 동등성이 아니다.

바다 안내 혼합 파티 지원은 `mysteryGuideMixedRule`이 있는 새 도전에만 적용한다. 복잡한 특수 폼·융합 및 알 수 없는 챌린지 판정은 기존 경로를 유지하고 별도 검증이 필요하다.
