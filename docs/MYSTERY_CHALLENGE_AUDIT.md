# 미스터리 이벤트 챌린지 대조 메모

고정 원본의 `src/data/mystery-encounters/encounters`와 `mystery-encounter-requirements.ts`, 이 프로젝트의 `lib/rogue-mystery.mjs`를 비교한 작업 메모다. 아래는 확인한 범위이며 전체 이벤트·폼·난수 동등성 표가 아니다. `source-subset-v1` 챌린지에 한해 판정이 불명확한 저장은 임의 허용하지 않는다.

| 이벤트·경로 | 원본에서 확인한 조건 | 현재 상태·다음 검증 |
| --- | --- | --- |
| Mysterious Chest | 출전 가능 생존자 2명 이상 출현; 함정은 그중 최고 레벨; 남은 출전 가능 개체가 없으면 패배 | 자연 출현, 함정·패배·전투·저장 복구를 구현·검사했다. |
| Berries Abound 경주 | 출전 가능 생존자 중 가장 빠른 개체가 경주 | 경주 승패·보상·전투 복구를 구현·검사했다. |
| The Strong Stuff | 출전 가능 생존자 3명 이상 출현; 주스는 파티 전체에 적용 | 출현과 주스 대상 구분, 챌린지 자연 출현 후 전투 복구를 검사했다. |
| Part Timer·Shady Vitamin Dealer | 수동 선택은 출전 가능 개체를 요구 | 화면 후보·서버 선택·저장 복구를 검사했다. 원본의 자동 후보 추첨과 RNG는 전체 동등성이 아니다. |
| Uncommon Breed 매료 | 출전 가능하고 지정 기술을 가진 후보 중 난수로 참가자 선택 | 새 도전은 추첨을 한 번 저장한다. 기존 도전은 이전 방식이며 원본 Phaser 시드·재평가 순서와 다르다. |

| Lost at Sea 방황 | 출전 가능한 생존자에게만 최대 HP의 25% 피해, 기절 방지 | 자연 출현·저장 복구 후 피해와 다른 슬롯 보존을 검사했다. |
| Lost at Sea 길 안내 | `CanLearnMoveRequirement.meetsRequirement`는 출전 가능자를 검사하지만 `queryParty`는 전달받은 파티를 기술 호환성으로만 거른다. 원본 옵션 처리에서 요구 조건 재평가·후보 추첨도 수행한다. | 새 도전의 검증된 기본 폼 파티는 선택지별 후보를 추첨해 저장한다. 기절·금지 개체 및 미검증 폼이 섞인 경우 기존 선택을 유지하므로 원본 후보 범위·재추첨·난수 상태 차이가 남는다. |
| Fiery Fallout 진정 | 원본은 기절 제외 타입 조건과 출전 가능 능력 조건을 조합한다. | 새 도전의 검증된 기본 폼 파티는 불꽃 타입 후보를 우선해 추첨하고 저장한다. 복잡한 파티는 기존 선택을 유지하며 능력 억제·패시브·폼과 원본 재추첨을 더 대조해야 한다. 뜨거운 바람은 출전 가능한 생존자에게만 적용한다. |
| Teleporting Hijinks 기계 조작 | `TypeRequirement`는 조건 충족 여부를 볼 때 기절한 개체를 제외하지만, 후보 조회 자체는 받은 파티에서 강철·전기 타입을 찾는다. 이 조건은 챌린지 출전 가능 여부를 확인하지 않는다. | 새 도전에서 검증된 기본 폼 파티는 생존 타입 조건을 확인한 뒤 전체 파티의 첫 강철·전기 타입을 선택한다. 원본 옵션의 일반 경로는 추첨 없이 첫 후보를 택한다. 기절 후보는 전투 승리 후 경험치를 받지 않는다. 기존 도전과 미검증 폼은 이전의 생존 후보 방식을 유지한다. |

검사에서 실제 계정의 전체 플레이나 원본 RNG 상태를 전수 재현한 것은 아니다. 원본에서 비활성인 이벤트는 활성화하지 않는다. 사용자의 최신 지시는 검증 후 매번 운영 배포이며, 현재 Sites 필수 소스 헬퍼 부재로 배포가 막혀 있다.

## 후속 원본 선택 순서 재검토

`mystery-encounter-option.ts`의 `meetsPrimaryRequirementAndPrimaryPokemonSelected` 일반 경로는 `qualified[0]`을 사용하며 지원 후보 중복을 제외하는 분기에서만 난수를 사용한다. 순간이동의 일반 후보는 첫 번째다. 바다 안내와 Fiery Fallout의 기존 저장 후보 난수 구현도 해당 옵션에 지원 후보 중복 분기가 적용되는지 다시 확인해야 하므로 원본과 같다고 단정하지 않는다. 기존 진행의 저장 후보와 RNG를 보존하면서 수정할 수 있는 별도 규칙 버전과 회귀 검증이 필요하다.
