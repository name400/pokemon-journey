## 확정한 재현 경로

기존 HEAD 코드에서49층 야생 고라파덕을 마스터볼로 포획해 자동 합류시키고,50층 야생 전투로 넘어가 고라파덕으로 교체했다. `tools:{}`, `teraCharged:false`인데 테라스탈 선택이 노출되고 `playClassicCombat(...,{type:'move',move:'splash',special:'terastallize'})`가 성공해 실제 `terastallized:'Water'`가 저장됐다. 단순한 왕관 잔상만의 문제가 아니다. `/tmp/astra-tera-baseline.log`에 위 값만 기록했다.

원인은 최초 전투 생성에서만 도구를 검사한 것이었다. 포획·파티 교체가 호출하는 `appendOwnedPokemon`은 native Pokemon의 기본 `canTerastallize`를 유지했고, 복구 경로는 특수 폼만 검사하여 이 권한을 다시 차단하지 않았다. 최초 파티만으로 진행하는 무오브 경로는 정상 차단돼 포획 후 추가 경계를 놓쳤다. 운영 사용자의 실제 저장/명령 이력이 없으므로 이 재현이 그 계정의 정확한 과거 이력이라고 단정하지 않는다.

## 원본 대조와 수정

고정 원본 `7c0881255af5cd51992e513ff93c2f71adbe40e0`의 `src/utils/pokemon-utils.ts`에서 `canSpeciesTera`는 TerastallizeAccessModifier와 Mega/Max/Ultra 제외를 검사하고, `canTerastallize`는 arena 사용 횟수도 검사한다. `src/ui/handlers/command-ui-handler.ts`는 더블의 예정된 사용도 합산한다. 현재 앱의 오브/충전·같은 특수 변화 중복 거부 규칙을 유지하면서 추가 개체에도 같은 검사를 적용했다. 원본의 모든 테라·폼·아이템 상호작용 동등성을 의미하지 않는다.

`lib/rogue-battle-engine.mjs`의 공통 준비/복구/최초 생성에서 파티원의 오브와 충전, 이미 사용한 진영, 특수 폼·native 제한을 재확인한다. 포획 자동 합류, 꽉 찬 파티 교체, 더블 중 합류와 연속 야생 새 상대에도 적용한다. 트레이너의 지정 즉시 테라 권한은 플레이어 도구와 분리한다. 보상으로 중간에 오브를 얻으면 기존 파티의 권한도 다음 복구에서 활성화할 수 있다.

combat에 도구·충전 상태를 함께 저장해 직접 DTO 복구도 같은 정책을 사용한다. 실제 게임 GET은 run의 현재 도구/충전을 전달하므로 이 metadata가 없거나 과거 허용 상태가 남은 저장에서도 버튼과 서버 명령을 차단한다. 클라이언트 버튼만 숨기는 수정이 아니다.

이미 정상 사용한 테라는 충전이 false여도 변신 자체를 지우지 않는다. 같은 야생 구간·교체·codec 뒤 유지와 새 사용 금지를 구분한다. 이번 수정은 이미 지나간 불법 테라의 피해·보상이나 저장된 변신 이력을 소급 되돌리지 않는다. 따라서 이미 변신한 현재 전투의 왕관이 이 수정만으로 즉시 사라진다고 보장하지 않는다. 다음 정상 전투 초기화 경계와 실제 사용자 저장의 표시 회복은 별도 확인이 필요하다.
