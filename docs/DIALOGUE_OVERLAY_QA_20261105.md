# 모바일 NPC 대화·하단 메뉴 겹침 수정

## 재현과 원인

수정 전 클라우드 HEAD `e0b5bb3`의 실제 페이지·대화 컴포넌트·CSS를 격리된 로컬 브라우저 환경에서 재현했다. 합성한 14웨이브 더블 트레이너전과 실제 게임 액션·뷰 함수를 사용했다. 실계정 데이터나 운영 API는 사용하지 않았다.

390×844에서 대화 패널은 y=676~830, 하단 메뉴는 y=775~844였다. 두 버튼은 y=774~818에 배치되어 건너뛰기는 ‘친구 · 프로필’, 다음은 ‘관리자’ 메뉴에 가로채였다. 실제 좌표 터치로 다음을 누르면 `tab=admin`으로 이동하는 것까지 확인했다. 원인은 `isolation:isolate`인 게임 영역의 쌓임 맥락 안에 있는 대화가 바깥의 메뉴 위로 올라오지 못하는 것이었다.

## 변경

대화를 `document.body` 포털로 렌더링해 게임 영역의 쌓임 맥락에서 분리했다. 하단 메뉴가 있는 화면에서는 메뉴 위로 간격을 확보하고 전장 기준 위치·리사이즈·스크롤 재계산을 유지한다. 서버에서는 포털을 렌더링하지 않고 클라이언트에서 연결하며 기존 글꼴·팔레트·키보드 포커스 동작을 유지한다. 저장 형식·전투 규칙·계정 API는 변경하지 않았다.

수정 후 390×844의 대화는 y=609~763, 다음 버튼은 y=707~751로 하단 메뉴(y=775~844)와 겹치지 않았다. 두 버튼의 중심에서 실제 버튼이 감지되고 터치가 처리됐다.

`tests/browser/dialogue-overlay/check.mjs`로 다음 네 크기를 모두 통과했다.

| --- | --- | --- | --- | --- | --- |
| 390×844 | 통과 | 통과 | 통과 | 통과 | 통과 |
| 375×667 | 통과 | 통과 | 통과 | 통과 | 통과 |

키보드는 초기 다음 버튼 포커스, Tab/Shift+Tab의 대화 내부 이동, Enter/Space의 다음 진행, Escape의 건너뛰기를 확인했다. 대화 중 새로고침·계속하기 후 동일한 진행 문장 복구, 버튼 히트 테스트와 화면 안 배치, 가로 넘침 없음, 브라우저 pageerror 없음도 확인했다. 대화가 열린 상태의 화면 크기 전환 후에도 실제 건너뛰기 터치로 닫힌다.

재실행 방법은 `tests/browser/dialogue-overlay/README.md`에 기록했다. 스크린샷은 무시 경로 `.sites-runtime/tests/dialogue-overlay/artifacts/`에 생성된다. 외부 이미지는 검사에서 SVG로 대체했으므로 자산 로드·실물 이미지 외형 검증은 아니다. 자연 진행으로 14웨이브에 도달한 실계정 플레이, 운영 배포본, 실제 모바일 기기와 Safari는 이번 검사 범위 밖이다. Sites는 변경하지 않았다.

전체 회귀 626개(실패·취소·건너뜀 0), `npm run typecheck`, `npm run build`와 `git diff --check`를 통과했다. 변경 파일 ESLint는 오류 0개이며 기존 NPC 초상화의 `@next/next/no-img-element` 경고 1개를 유지한다. 별도 SSR 회귀는 서버 렌더 중 `document` 접근이나 포털 생성 없이 완료됨을 검사한다.
