# Battle-zone bonus and medal save guard

The Z-A Royale uses bonus cards and prize medals as part of progression ([overview](https://www.pokemon-france.com/en/guides/pokemon-legends-z-a/z-a-royale/)). In the existing implementation, completing a card with an unrecognized `zaRoyalePrizeMedals` value replaced that value with the new numeric reward; an unrecognized point balance was similarly normalized. This was reproduced directly with a versioned medal object. Battle victory accounting could also replace unknown medal-night, win-count or trainer-history data.

Card completion now leaves the card, points and medals untouched when the relevant stored values cannot safely be interpreted, or when a positive medal balance belongs to a different night. A log message reports the blocked payment. After the data or old-night balance is resolved, the player must perform a matching action again while the card remains valid; this change does not create a persistent pending-payment queue or extend card expiry. Existing numeric reward amounts and caps remain project approximations, and are not claimed to match the original. Normal battle outcome accounting also refuses to alter unknown medal records. No existing save is migrated or repaired automatically.

Unit checks exercise invalid point, medal, night, win and trainer-history formats, both battle outcomes, a previous-night balance, retry and single payout. An isolated API check uses an actual battle turn and reconnect to check preservation and subsequent payout after the fixture balance is made valid; the fixture correction is test-only. A representative existing card completion test also passed. Full test suite, production D1, original hardware and the Sites merged source were not checked.
