# 친구 접속 상태의 프로필 갱신 순서 — 2026-11-18

격리 SQLite에서 실제 프로필·활동·친구 API 코드를 사용해, 최근 활동 시각이 기록된 뒤 더 오래된 시각의 프로필 갱신이 처리되는 순서를 재현했다. 기존 `ensureProfile`은 새 활동값을 이전 값으로 덮어썼다. 예를 들어 최근 활동 후 80초에는 온라인이어야 하지만 20초 오래된 값으로 되돌아가면 90초 기준에서 오프라인으로 표시될 수 있다. 수정 전 신규 검사는 활동 시각 1,120,000 대신 1,100,000을 관측해 실패했다. 시계를 제어한 순서 재현이며 실제 운영 D1 경합을 관측한 것은 아니다.

프로필 upsert에서 저장된 활동 시각과 요청 시각의 최댓값을 저장하도록 수정했다. 이메일·이름 갱신과 기존 친구·저장 데이터는 유지한다. 수정 후 실제 프로필 코드를 포함한 격리 API 검사에서 과거 갱신의 역행 방지, 마지막 활동 후 89,999ms 온라인·90,000ms 오프라인, 재접속, 수락 전 및 비친구 비노출을 확인했다. 기존 동일 출처·인증, 활동 갱신 및 친구 요청·수락·삭제를 포함해 총 5건이 통과했다.

소유권을 확인한 전용 격리 Vite 서버와 Chromium 1280×800·390×844에서는 친구 상태 표시, 대기 요청 비노출, 갱신 및 네트워크 재연결 후 활동 요청을 확인했다. 이 브라우저 검사의 친구·활동 응답은 모의이며 실제 SQLite API와 연결한 화면 검사는 아니다. 종료 후 오프라인 표시는 활동 만료와 목록 갱신을 기다린다. 실제 계정·운영 D1의 분산 지연·물리 기기는 확인하지 않았고 Sites에는 배포하지 않았다.

후속 검토에서는 오래된 시각으로 준비된 실제 프로필 upsert를 격리 API 시험에서 잠시 보류한 뒤, 새 heartbeat가 먼저 저장되도록 하고 프로필 처리를 재개했다. 최근 시각과 온라인 표시가 유지됐고 총 6건이 통과했다. 기존 `players.last_seen`은 `NOT NULL`이며 컬럼이나 저장 형식 변경 없이 SQLite upsert의 기존 정수 값을 사용한다. 이 시험은 처리 순서를 제어한 단일 SQLite이며 운영 D1의 분산 동시성을 보장하지 않는다.
