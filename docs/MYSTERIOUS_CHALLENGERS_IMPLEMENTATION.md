# 원본 도전자 이벤트 연결 기록

이 문서는 제공 ZIP의 소스에서 확인한 규칙과 현재 연결 상태를 구분한다. 현재 이벤트가 플레이에 노출됐다는 문서가 아니다.

## 확인한 원본
- src/data/mystery-encounters/encounters/mysterious-challengers-encounter.ts
- src/data/mystery-encounters/mystery-encounter-biomes.ts
- src/data/mystery-encounters/utils/encounter-phase-utils.ts
- src/field/arena.ts randomTrainerType, src/battle-scene.ts applyPartyExp

## 이벤트의 원본 규칙
- GREAT 등급, 인간 활동이 있는 바이옴의 일반 이벤트 후보. 일반/어려움/극악 세 선택지이며 이탈 선택지는 없다.
- 일반은 바이옴의 일반 트레이너. 어려움은 다른 일반 트레이너를 최대 5회 재추첨해 선택하며 선두 STRONGER 1마리와 AVERAGE 균형 파티 min(ceil(wave/20),5)마리로 구성한다.
- 극악은 바이옴의 보스 트레이너를 ELITE_FOUR 템플릿으로 구성하며 기존 관장 템플릿 함수를 덮어쓴다.
- 어려움의 levelAdditiveModifier는 1, 극악은 1.5. 실제 가산은 max(round(wave/10*modifier),0)이다. 최신 지시로 포켓로그의 임의100레벨 제한은 철회됐으므로 가산 후 레벨을100으로 자르지 않는다.
- doubleOnly는 더블로 진행한다. 그 외 일반 클래스의 무작위 더블 추첨을 추가하지 않는다. 원본은 초기 후보 구성에서 성별을 정하고 선택 후 팀 생성에 별도 시드 오프셋 wave*10/100/1000을 사용한다.
- 일반 보상은 TM_COMMON, TM_GREAT, MEMORY_MUSHROOM을 보장하고 나머지 선택 수를 채운다. 어려움은 [ULTRA,ULTRA,GREAT,GREAT], 극악은 [ROGUE,ROGUE,ULTRA,GREAT] 등급을 보장한다. 한 가지 보상을 선택하는 절차다.
- 원본은 극악 선택 때 expMultiplier=0.9를 설정한다. 다만 실제 applyPartyExp에서는 TRAINER_BATTLE의 1.5배 분기가 먼저 적용되고 미스터리 배율은 else-if이다. 의도 주석만 보고 트레이너 경험치에 임의 0.9배를 추가하지 않는다. 실제 원본 실행 경로를 검사할 필요가 있다.

## 현재 구현한 공용 부분
- 미스터리 레벨 보정을 classicMysteryLevelAdditive로 연결하고, 기존 ‘트레이너의 시험’의 평면 +1을 원본의 웨이브 비례 가산으로 수정했다. 현재 저장된 진행 중 전투의 레벨을 소급 변경하지 않는다.
- 기억버섯은 이미 공용 서비스/무료 보상 처리에 구현되어 있었다. 상점 해금 전 무료 보상 사용, 기술3개일 때 네 번째 칸 추가, 돈 미소비, 잘못된 기술 거절 및 파티 보존 검사를 추가해 이벤트 보상에서 재사용 가능한 경로를 확인했다. 별도의 중복 기억버섯 구현은 추가하지 않았다.

## 남은 이벤트 연결
1. 원본 바이옴 후보 추첨과 세 트레이너/성별 설정을 저장하고, 선택 전에는 원본처럼 실루엣/난이도로 제시.
2. 파티 템플릿 덮어쓰기 및 선택별 시드 오프셋을 공용 트레이너 생성기로 연결.
3. 선택·취소·확인, 실제 배틀 진입, 기절/승패, 원본 대화 및 재접속을 연결.
4. 원본 보장 보상·추가 선택 수·리롤·학습 처리와 경험치의 실제 원본 분기를 검증.
5. 위 경로가 연결되기 전에 후보 목록이나 UI에 구현된 이벤트로 표시하지 않는다.

## 원본 비활성 이벤트
AN_OFFER_YOU_CANT_REFUSE는 mystery-encounter-biomes.ts에서 Disabled로 주석 처리되어 있다. 개별 이벤트 파일이 있다는 이유만으로 일반 플레이에 활성화하지 않는다. BERRIES_ABOUND 등 다른 후보도 원본의 활성 여부를 직접 확인해야 한다.

## 클라우드 재개 — 기초 템플릿
- 태그가 가리키는 `059130acaaea04a3c1edc519dc6cb8ef154bcc48`과 별도 원본 `7c0881255af5cd51992e513ff93c2f71adbe40e0`을 확인했다.
- 어려움 파티의 STRONGER 1마리와 AVERAGE 최대 5마리, 밸런스 및 진화 기준을 생성하는 독립 함수를 추가했다. 20·21·40·41·80·81·100·200웨이브 경계 단위 검사를 통과했다.
- 함수는 아직 전투 생성기나 이벤트에 연결되지 않았으며 저장, 선택, 배틀, 보상과 실플레이 검증이 모두 남아 있다. 이벤트를 후보에 추가하지 않았다.
- 이 환경의 기본 npm 캐시 경로는 쓰기 제한으로 설치가 실패했다. `npm_config_cache=/tmp/pokerogue-npm-cache npm run install:ci`로 설치했다.
- 클라우드에서 전체 자동 검사 338/338, 타입 검사와 빌드가 통과했다. 이는 이벤트 통합이나 자연 200웨이브 실플레이의 검증이 아니다. `AGENTS.md`는 인계 체크아웃에 없었으며 기존 사본의 게임 UI 관련 스킬을 읽었다.

## 클라우드 후속 작업 — 후보와 전투 생성 기반
- 바이옴별 일반/보스 후보 풀과 성별을 이용해 세 후보를 미리 추첨하는 함수를 추가했다. 어려움 후보가 일반과 같으면 최대 5회 재추첨하며 후보 객체는 JSON 직렬화할 수 있다. 기존 게임의 저장 난수 커서를 사용하므로 원본 시드 알고리즘과 완전 동일하다는 뜻은 아니다.
- 공용 트레이너 생성기에 이 이벤트 전용 어려움/ELITE_FOUR 템플릿 오버라이드, 후보 성별과 doubleOnly 처리를 추가했다. 이벤트 전용 오버라이드는 기존 `trainerTemplates` 선택을 바꾸지 않는다. 실제 생성 파티의 레벨, 더블 전용 트레이너와 전투 JSON 복원 검사를 수행했다.
- 후보 추첨과 전투 생성기는 아직 이벤트 발생·선택 화면과 연결하지 않았다. 선택 확인/취소, 후보를 진행 저장에 기록하는 호출, 팀 생성 시 원본 seed offset, 대화·보장 보상·리롤·승패 흐름 및 실플레이가 남아 있다. 이벤트는 계속 비활성이다.
- 후속 변경 중 전체 검사 340/340, 타입 검사와 빌드가 통과했다. 그 뒤 후보 재추첨 함수를 분리하고 경계 검사를 추가했으며 최종 변경본의 관련 검사 7/7이 통과했다. 분리 후 전체 검사는 다시 실행하지 않았다.

## 클라우드 후속 연결
- 신규 도전의 `challengerRule: source-v1`에서 인간 활동 바이옴 GREAT 후보로 등장하며 세 후보와 성별을 진행 상태에 저장한다. 기존 도전에는 새 규칙을 소급 설정하지 않는다. 선택·취소·확인, 전투, 승패, 원본 한국어 대화, 보상과 리롤을 연결했다. 클라이언트 조회에서는 선택 전 후보 데이터를 숨긴다.
- 난이도별 원본의 UTF-16 시드 오프셋을 별도 Phaser 방식 난수 스트림에 적용하고 원래 저장 난수 커서를 복원한다. 현재 파티 생성기의 무작위 호출 순서 및 게임 전체 시드 호환성이 원본과 동일하다는 뜻은 아니다.
- 최초 보상은 일반 TM 2종(생성 가능할 때)과 기억버섯, 어려움 ULTRA/ULTRA/GREAT/GREAT, 극악 ROGUE/ROGUE/ULTRA/GREAT 및 추가 슬롯을 처리한다. 보장 등급의 운 상승을 적용한다. 원본에서 리롤은 보장 설정 없이 일반 보상으로 돌아가는 것을 확인했다. 원본의 중복 보상 재추첨까지 완전히 재현하지는 않았다.
- 적 생성 중 발견한 총지엔·위유이 특성 누락은 시뮬레이터의 특성 번호 중복 때문이었다. 원본 특성 enum 이름을 기준으로 네 재앙 특성을 명시적으로 매핑했다.
- 선택·취소·JSON 복원, 세 난이도 전투 진입, 보상·패배·리롤과 기존 저장 분리를 격리 자동 검사했다. 브라우저 실플레이, 모바일 화면, 자연 200웨이브와 원본 난수·보상 중복 규칙 전체 대조는 미검증이다.

## 다음 항목 — 이상한 꿈 조사

- 첫 선택은 미리 계산한 변환 파티를 적용·회복하고 기억버섯/로그볼/민트 보상을 제시한다. 둘째는 변환 파티와 전투하고 승리 시 이번 도전에만 패시브 하나를 해금하며 6개 등급 보상을 제시한다. 셋째는 파티 레벨을 각각 `max(ceil(level*0.9),1)`로 낮추고 경험치를 새 레벨의 시작값으로 맞춘다.
- 변환 후보의 종족값 범위·제외 종·폼·소지품·기존 데이터 보존과 재접속을 원본의 `getTeamTransformations` 및 후처리와 대조해야 한다. 위 조사는 구현이 아니며 이벤트는 계속 미연결이다.
- 28개 후보 바이옴 × 35개 시드 × 3개 웨이브 × 3개 난이도에서 원본 오프셋 난수 경로로 파티 8,820개 생성에 성공했다. 이 검사는 실제 플레이나 모든 가능한 시드·종 조합의 보장은 아니다.
- 변환 대상은 파티 순서를 섞어 첫 두 마리에 종족값 +90~110, 나머지에 +40~50 범위를 사용한다. 후보가 20종 이하일 때 범위를 양쪽으로 10씩 넓히며 원래 파티와 이미 고른 종을 피한다. 570~600 및 600 초과는 각각 한 마리만 허용한다.
- 변환 후 원본은 기존 도구 중 폼 변화 도구를 제외하고 이동, 이전 포켓러스·행운·패시브를 보존하며 개체치·중립 성격·알기술·자속 기술·두 번째 타입을 다시 정한다. 영구 스타터 등록과 사탕 지급 조건은 배틀용 변환과 다르므로 선택지별로 구별해야 한다.
- 마지막 코드 변경 후 전체 자동 검사 350/350, 타입 검사와 빌드가 통과했다. 빌드에는 기존 시뮬레이터의 `eval` 및 큰 청크 경고가 있다.

## 후속: 보상 중복과 개별 파티원 시드
- 수수께끼 도전자 보상에서 원본의 최대 `min(보상 수*5,50)`회 재추첨 구조를 적용했다. 후보가 같은 표시 이름 또는 그룹이면 해당 후보의 등급을 유지해 다시 뽑고, 최대 횟수에 도달하면 마지막 결과를 사용한다. 볼·교환권·TM·루어·회복·부활·PP·열매의 확인된 공통 그룹을 매핑했다. 나머지 지원 아이템의 원본 그룹 전수 대조는 미완료다.
- 원본 `Trainer.genPartyMember`가 난이도 오프셋 안에서도 각 파티원의 시드를 별도로 설정하는 것을 확인해, static party·동일 시드 플래그·파생 트레이너 타입을 반영했다. 단일 후보 추첨에서 불필요한 난수 소비도 피한다. 개별 함수의 전체 호출 순서와 원본 종 선택·보상 풀은 아직 일치한다고 보장할 수 없다.

## 후속: 이상한 꿈 구현 준비
- 원본 종족값 범위, 확장, 종 중복 배제, 570~600 및 600 초과 각각 한 마리 제한과 제외 종 목록을 적용하는 독립 후보 계획기를 추가했다. 이전 파티 순서의 결과를 반환하고 원본 데이터가 부족할 때 무한 반복 대신 오류를 낸다.
- 거절 선택의 레벨 90% 올림 및 현재 레벨의 상대 경험치 0, HP 상한·기절·상태 보존을 독립 함수로 구현하고 입력 불변성을 검사했다. 다이맥스 중에는 지원하지 않는다.

## 이상한 꿈 후속: 변환 구성 요소
- 기존 기술의 남은 PP·PP 상승을 보존하면서 알기술과 새 종의 자속/대체 기술을 삽입하는 함수, 새 특성의 두 번째 숨겨진 특성 추첨, 중립 성격, 이전 개체치 상속과 HP 비율·상태·포켓러스·행운 보존을 조합하는 독립 함수를 추가했다. 전투용은 새 포켓몬을 정상 체력으로 만든다. 융합·특수 폼은 아직 거절한다.
- 원본은 이전 포켓몬 개체치를 물려주기 전에 새로 굴린 개체치를 도감에 기록한다. 이 값을 따로 보존하고 도감·사탕·알기술 해금을 별도 시스템 사본에 적용하는 함수를 만들었다. 전투용과 미포획 고종족값 비색이는 계정 기록을 바꾸지 않는 경로를 검사했다.
- 폼 도구 이외의 소지 효과는 이동 불가 속성도 포함해 새 소유자에 복사하는 함수와, 원본의 옛날과자 최저 능력치 세 쌍 선택을 추가했다. 원본 파티·소지 효과·계정 입력은 변경하지 않는다.
- 함수는 아직 이벤트나 실제 저장에 연결되지 않았다. 최초 변환 종·특성·색·랜덤 타입 생성 순서, 옛날과자 실제 능력치 효과, 도구/폼/융합의 완전한 지원, 파티 일괄 반영, 전투·복원·선택·대사·보상 및 자연 플레이가 남았다. 이 기능을 완성했다고 표시하지 않는다.
- 파티 전원의 변환 초안·도구 소유자 변경·도감 결과를 원본과 별도의 run/system 사본으로 일괄 생성하는 단계 함수를 추가했다. 이전 및 신규 식별자 중복, 개체치, 현재 미지원인 네이티브 소지 도구와 폼 도구를 확인해 오류 시 입력을 유지한다. 저장 엔진에 이 결과를 적용하는 호출은 아직 없다.
- 초안·소지 도구·계정 결과의 JSON 왕복과 오류 시 입력 보존을 격리 검사했다. 이는 서버 저장 트랜잭션이나 전투 재접속, 모든 아이템·특수 폼의 실동작 검증이 아니다.
- 전체 자동 검사 363/363, 타입 검사와 빌드가 통과했다. 전체 검사를 시작한 뒤 새 식별자와 기존 도구 기록의 충돌 거절을 추가했으며, 그 최종 변경은 관련 검사 11/11로 따로 확인했다. 전체 검사는 최종 가드 추가 후 다시 시작하지 않았다.

## 이상한 꿈 후속: 옛날과자·저장·대체 배틀
- 옛날과자는 원본처럼 원래 종의 HP/스피드, 공격/특공, 방어/특방 중 낮은 쪽에 각각 +20을 적용한다. 동률은 각 쌍의 후자를 선택하며, 주스 다음·비타민 이전에 적용한다. 변환된 소유자의 이동 불가 도구로 기록하고 실제 전투 능력치와 JSON 복원을 검사했다.
- 보유한 주스·비타민·마음의물방울·교정깁스의 파생 능력치를 새 종에서 다시 계산한다. 원래 저장 상태는 보존하고, 일반 폼으로 변환될 때 이전 폼 변화 도구는 원본처럼 이전하지 않는다. 이전 메가 등 비다이맥스 폼은 제한적으로 다루지만 새 특수 폼·융합·다이맥스 및 네이티브 소지 도구는 안전하게 거절한다.
- 확정된 서버 측 변환 초안을 별도 run/system에서 검증한 후 저장 문서의 해당 슬롯과 계정을 한 번에 교체하는 내부 함수를 추가했다. 중복 확정은 거절하고, 실패 시 원본 문서와 다른 슬롯·탐험 데이터는 보존된다. API의 기존 저장 revision 검사는 별도로 유지한다.
- 대체 파티의 비이동 소지 효과·보스 여부·옛날과자를 준비하고 실제 트레이너 전투 스냅샷을 저장·복원하는 내부 경로, 승리 시 6개 등급 보상 생성기를 추가했다. 아직 일반 이벤트 선택·대사·승패 후 처리와 연결하지 않았으며 서버 저장 API의 실제 통합 검증도 아니다.
- 민트 보상과 이번 도전만의 패시브 해금, 융합·다이맥스·새 특수 폼·네이티브 소지 도구, 종 생성 및 난수 호출 순서, 세 선택지 UI와 자연 진행이 남아 있다. 이벤트는 계속 비활성이다.
- 변환 확정 내부 함수에는 원본처럼 새 파티 중 패시브가 없는 포켓몬 한 마리의 패시브를 이번 도전에만 활성화하는 단계도 넣었다. 도감의 영구 패시브 구매 정보는 변경하지 않는다. 대체 배틀 승리 시 적용은 아직 게임 흐름에 연결되지 않았다.
- 마지막 코드 기준 전체 자동 검사 371/371, 타입 검사와 빌드가 통과했다. 자연 200웨이브 및 브라우저 실플레이는 수행하지 않았다.

## 이상한 꿈 후속: 제한된 실제 흐름
- 위의 ‘비활성’ 표기는 이전 단계 기록이다. 신규 도전의 `weirdDreamRule: source-subset-v1`에서 지원되는 3마리 이상 파티는 원본 조건의 이상한 꿈 후보를 실제로 만날 수 있다. 기존 도전은 소급 활성화하지 않는다. 융합·다이맥스·네이티브 소지 도구·스케치 특수 저장 및 미해석 종은 제외하며, 선택 직전 변환 초안과 난수 커서를 저장한다.
- 선택·취소·확인, 대화, 파티 변환 및 전체 회복, 떠나기와 레벨 감소, 대체 파티 전투·패배·승리·패시브·보상 및 리롤을 연결했다. 실질 성격을 원래 성격과 분리해 저장하는 민트와, 기억버섯·로그볼·민트 4개의 보상을 추가했다. 100레벨 상한이라는 오래된 파티 안내 문구도 제거했다.
- 원본의 시드 알고리즘과 호출 순서, 종 풀과 자산, 기술 생성·보상 중복 및 모든 특성 상호작용이 완전히 같은 것은 아니다. 대체 플레이어 초상은 일반 대체 그림이며, 융합·다이맥스·새 특수 폼·네이티브 소지 도구 처리와 실제 운영/브라우저/모바일 검증은 남았다. 제한된 구현을 원본 전체 동등성으로 간주하지 않는다.
- 격리 저장에서 자연 후보 발견, 모든 선택과 저장 복원, 실제 턴 전투와 승리·패배, 보상/다음 웨이브, 도감 및 탐험 데이터 보존을 검사했다. 후보 생성은 여러 시드·파티 조합을 표본으로 확인했으며 모든 종과 시드의 전수 검사는 아니다.
- 진행 중인 기술 학습·성장·포획·진화가 남아 있는 저장은 꿈의 파티 교체를 준비하지 않으며, 저장 반영 시에도 다시 확인한다. 지원하지 않는 기존 폼/도구에서 기존 파티와 관련 기록을 임의로 삭제하지 않는다.
- 원본 대체 플레이어 트레이너는 상금 배율 0이다. 도전 재화 계산에서 0을 기본 배율 1로 오해하던 처리를 수정했고, 대체 배틀 승리 후 도전 소지금 불변을 검사했다.
- 최종 코드 기준 전체 자동 검사 389/389, 타입 검사와 빌드가 통과했다. 대체 파티의 실제 엔진 턴 진행과 저장 인코딩 복원을 격리 테스트했지만 브라우저·실기기·운영 저장으로 검증하지 않았다.

## 후속 작업: 네이티브 도구와 브리더·광대 기반 (운영 미배포)
- 이상한 꿈은 기존의 네이티브 도구 전체 제외에서 먹다남은음식, 화염구슬, 맹독구슬만 허용하도록 확장했다. 변환 시 소지 도구를 유지하고 대체 배틀 복제 도구는 이전 불가로 설정한다. 자연 조우·변환·저장 왕복, 도둑질 방지와 화염구슬 자체 효과를 자동 검사했다. 다른 네이티브 도구와 융합·다이맥스·새 특수 폼은 여전히 안전하게 제외한다.
- 브리더는 원본의 친밀도 하위 참가 후보, 종족값·스타터 비용에 따른 일반/레어 알 수, 웨이브별 상대 종 후보와 우주 바이옴 고정 팀, 단독 전투 파티 분리/복원과 승패 친밀도 처리, 알 보관함 초과 대기열과 중복 지급 방지를 독립 함수로 구현했다. 원본 고정 선두와 우주 팀을 실제 전투 엔진·JSON 복원으로 확인했다. 일반 알의 이벤트 지급도 지원한다.
- 광대는 세 번째 선택지의 공격 기술 타입 우선 추첨과 예비 타입 추첨을 순수 계획 함수로 구현했다. 타입 변경 저장·진화/폼 지속성·전투 및 나머지 선택지 연결은 남았다. 융합은 계획 단계에서 거절한다.
- 브리더와 광대는 아직 실제 미스터리 출현, 선택 화면, 전투 승패 및 보상에 연결하지 않았고 공개하지 않았다. 브리더의 일반 상대 기술 생성과 난수 호출은 원본 완전 일치가 아니며 자연 플레이 검증도 아니다. 기존 문서의 전체 도구 제외 설명은 위 세 도구에 한해 이 항목으로 대체한다.
- 최종 코드 기준 전체 자동 검사 400/400, 타입 검사 및 빌드 통과. 별도 브라우저 실플레이와 운영 저장 검증은 수행하지 않았다.
- 추가 후속: 광대 타입 선택 결과를 파티·난수 커서와 함께 별도 run 사본에 준비하고 실제 전투 엔진의 타입 및 전투 스냅샷 복원을 검사했다. 원본 저장은 변경하지 않는다. 아직 진화·폼 변경 시 커스텀 타입 유지와 실제 이벤트 흐름은 연결하지 않았으므로 출현은 비활성이다.
- 추가 후속의 최종 코드 기준 전체 자동 검사 402/402, 타입 검사와 빌드 통과. 브라우저 실플레이는 하지 않았다.

## 후속: 광대 타입의 진화·폼 및 브리더 전투 준비
- 광대의 저장된 두 번째 타입을 진화와 도구로 바꾸는 폼에 유지한다. 원본처럼 첫 타입은 새 종·폼을 따르며 둘이 같으면 표시 및 전투 타입에서 중복을 제거하되 커스텀 기록은 유지한다. 진화와 메가진화, JSON 복원 및 기존 타입 불변을 검사했다. 광대 출현·선택과 나머지 경로는 아직 연결되지 않았다.
- 브리더가 선택한 포켓몬 한 마리만을 사용하는 실제 전투를 파티와 소지 효과를 보관한 별도 run 사본에 준비하고 전투 스냅샷 복원을 검사했다. 이 준비 단계는 현재 사용자 진행에 연결하지 않았다. 실제 출현·선택·승패에 따른 파티 복구와 알 지급은 여전히 연결해야 한다.
- 꿈의 융합·다이맥스·새 특수 폼과 미검토 네이티브 도구는 계속 제한되어 있다. 운영 배포와 브라우저 실플레이는 하지 않았다.
- 이 후속 최종 코드 기준 전체 자동 검사 404/404, 타입 검사와 빌드 통과. 자연 브라우저 실플레이는 미실시.

## 후속: 브리더 제한된 실제 경로 연결
- 이전 ‘브리더 비활성’ 기록을 이 항목으로 대체한다. 새 도전의 `expertBreederRule: source-subset-v1`에서 지원 조건을 충족하는 브리더를 울트라 후보로 실제 출현시킨다. 기존 도전은 소급 활성화하지 않는다. 현재 인간 바이옴, 25~180 웨이브, 생존 네 마리 이상, 도전과제 없음 등 기존 후보 제한을 유지한다. 원본의 모든 바이옴·파티 조건을 지원한 것은 아니다.
- 친밀도 순 세 후보 선택과 취소·확인, 단독 트레이너 전투, 승리·패배 후 나머지 파티와 소지 효과 복원, 패배한 참가자의 친밀도 0, 승리 친밀도와 일반/레어 알, 알 보관함 대기열, 평온의방울 선택 보상과 나머지 보상 생성을 연결했다. 원본 대사 일부와 출처 고지를 추가했다. 알 지급 전 기존 알의 웨이브 경과를 처리해 새 알이 즉시 감소하지 않게 한다.
- 자연 후보 출현, 기존 도전 비활성, 저장 후 승패 복구, 선택 참가자와 대기 파티·도구·다른 슬롯·탐험 데이터 보존, 중복 지급 방지, 실제 엔진 턴 승리와 대사·저장 복원을 격리 자동 검사했다. 일반 상대 기술 및 난수 순서와 모든 보상 후보의 원본 동등성, 브라우저·운영 실플레이는 검증되지 않았다.
- 광대는 아직 실제 출현·전투·보상에 연결되지 않았고, 이상한 꿈의 미지원 폼과 도구도 남아 있다. 운영 배포하지 않았다.
- 브리더 연결 최종 코드 기준 전체 자동 검사 408/408, 타입 검사와 빌드 통과. 브라우저 및 운영 저장 실플레이는 미실시.

## 후속: 광대의 제한된 실제 경로와 꿈의 생명의구슬
- 이전 광대 비활성 기록을 이 항목으로 대체한다. 새 도전의 `clownRule: source-subset-v1`에서 지원되는 일반 파티는 울트라 후보로 광대를 만날 수 있다. 기존 도전은 소급 변경하지 않는다. 현재 생존 두 마리 이상, 도전과제·융합·특수 폼·네이티브 소지 도구가 없고, 옮길 수 있는 소지 효과나 열매가 없는 파티만 허용한다. 따라서 도구 재추첨 선택은 이 제한된 경우에 원본처럼 교체할 도구가 없어 그대로 지나간다. 도구가 있는 파티의 재추첨은 아직 구현하지 않았다.
- 세 선택지와 취소·확인, 고정 두 상대의 더블 배틀·역할극·양쪽 도발, 승리 후 특성 변경 또는 거절, 일반 보상, 패배, 파티 두 번째 타입 변경과 저장 복원을 연결했다. 상대 특성·타입 및 타입 선택은 저장된 난수 커서로 준비한다. 원본의 전체 난수 호출·소지 도구 풀 및 모든 특수 상호작용과 완전 일치는 아니다.
- 자연 출현과 기존 저장 비활성, 세 선택지, 전투·복원·실제 턴 진행, 승패·특성 변경/거절, 다른 저장·탐험 데이터 보존을 격리 검사했다. 브라우저 실플레이와 운영 검증은 하지 않았다.
- 이상한 꿈의 검토된 네이티브 도구에 생명의구슬을 추가했다. 변환 소지 유지, 대체 파티의 복제와 탈취 방지, 실제 전투의 반동을 검사했다. 다른 미검토 네이티브 도구와 융합·다이맥스·새 특수 폼은 계속 제외한다. 꿈의 원본 출현·난수·보상 차이도 남았다.
- 이 후속 최종 코드 기준 전체 자동 검사 418/418, 타입 검사와 빌드 통과. 실제 브라우저·운영 저장 검증은 미실시.

## 후속: 광대 열매 재추첨과 검토한 폼·꿈 도구
- 앞 항목의 ‘열매가 없는 파티만 허용’은 이전 상태다. 옮길 수 있는 일반 소지 효과가 없고 검토된 열매만 가진 파티는 광대를 만날 수 있다. 도구 선택 시 원본처럼 대상의 열매를 제거하고 고정된 11종 풀에서 종류별 수량 한도를 지키며 재추첨한다. 이 제한에서는 일반 소지 효과 수가 모두 0이므로 첫 파티원이 대상이다. 다른 파티원과 비이동 도구는 보존한다. 알 수 없는 열매 기록·추가 메타데이터 및 생성 풀 수용량을 초과하는 저장은 안전하게 제외한다.
- 옮길 수 있는 일반 도구의 등급별 재추첨은 아직 구현하지 않았다. 원본 울트라 풀의 황금주먹 등 이 프로젝트에 구현되지 않은 효과와 도구별 능력치 반영을 먼저 처리해야 한다. 융합·다이맥스·대부분의 특수 폼과 네이티브 소지 도구도 광대 출현에서 계속 제외한다.
- 안정적인 네이티브 폼인 암컷 에써르는 예외적으로 광대에 허용한다. 타입 변경 후 실제 전투 스냅샷 복원에서 암컷 폼과 변경된 타입을 확인했다. 이는 다른 폼이나 융합 전체 지원이 아니다.
- 이상한 꿈의 네이티브 도구에 구애머리띠·구애안경·구애스카프를 추가했다. 변환과 대체 전투 소지 유지·탈취 방지 및 구애머리띠의 전투 기술 고정과 복원을 검사했다. 다른 미검토 도구 및 새 특수 폼·융합·다이맥스는 여전히 제외한다.
- 열매 재추첨은 100개 시드에서 수량·풀 한도·입력 저장 보존을 검사했고, 실제 선택/저장 복구에서 다른 파티의 열매와 비이동 도구·다른 슬롯·탐험 데이터의 보존을 확인했다. 원본 시드 생성기 및 전체 난수 순서 일치는 주장하지 않는다. 브라우저 실플레이·운영 배포는 하지 않았다.
- 이 후속 최종 코드 기준 전체 자동 검사 423/423, 타입 검사와 빌드 통과. 브라우저 및 운영 저장 검증은 미실시.

## 후속: 황금주먹과 광대 일반 소지 도구
- 황금주먹은 신규 도전의 `goldenPunchRule: source-v1`에서 실제 적에게 기술로 입힌 각 명중 피해의 `floor(피해 × 0.5 × 중첩)`을 즉시 지급하며 부적금화 배율과 최대 안전 정수 상한을 적용한다. 울트라 보상 풀(199웨이브 전)과 광대의 울트라 도구 풀에서 획득할 수 있다. 구형 도전은 소급 활성화하지 않는다.
- 실제 단일·다중 타격·더블 배틀, 대타·면역·마지막 일격, 저장 복원과 중복 지급 방지, 집게손톱으로 빼앗은 다음 명중부터 지급, 5중첩 한도, 일반 보상 선택 및 광대가 만든 도구의 다음 전투 사용을 자동 검사했다. 브라우저 실플레이와 모든 기술/전투 효과의 전수 검사는 아니다.
- 앞 항목의 ‘일반 도구 제외’는 이전 상태다. 검토된 이동 가능 소지 도구를 가진 신규 규칙 파티는 원본처럼 비열매 도구 수가 가장 많은 포켓몬을 골라 열매, 울트라, 로그 풀 순서로 재추첨한다. 행복의알·평온의방울은 울트라, 황금알은 로그로 취급하고, 마스터 등급 멀티렌즈는 그대로 둔다. 마음의물방울 제거·재생성 시 성격 능력치를 다시 계산한다. 다른 소유자와 이동 불가 도구는 보존한다.
- 원본 타입 강화 도구 생성은 기존 타입 가중 풀을 사용하며 원본 RNG 전체 순서와 모든 세부 효과의 동등성은 아직 확인하지 못했다. 미검토 도구·네이티브 아이템, 보존 대상과 생성 풀이 충돌하는 저장, 필요한 전투 규칙이 없는 저장 등은 계속 안전하게 제외한다. 100개 시드와 자연 출현·선택·저장 복원 경로에서 등급별 수량과 다른 슬롯·탐험 데이터 보존을 검사했다.
- 광대의 안정적인 특별 폼으로 뾰족귀 피츄도 검토·허용했고 타입 변경 후 실제 전투 복원에서 폼을 확인했다. 융합·다이맥스와 대부분의 다른 특수 폼은 광대와 이상한 꿈에서 여전히 제한한다. 꿈의 미검토 네이티브 도구 및 원본 출현·난수·보상 차이도 남아 있다. 운영 배포하지 않았다.
- 이 후속 최종 코드 기준 전체 자동 검사 440/440, 타입 검사와 빌드 통과. 보스 체력 구간에서 실제 피해 기준 지급과 서투름 보유자의 지급도 별도로 확인했다. 브라우저 및 운영 저장 검증은 미실시.
