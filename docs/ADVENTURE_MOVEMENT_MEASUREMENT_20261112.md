# 탐험 이동 측정 — 2026-11-12

기준 커밋 `d894e0a`. 운영 서비스나 실제 휴대폰이 아닌 로컬 Chromium의 390×844 화면에서 UI 테스트용 프로덕션 빌드와 모의 `/api/world`를 사용했다. CPU는 DevTools의 4배 감속, 응답은 이동 요청당 150ms 또는 600ms로 지연했다. 캐릭터 첫 위치 변경은 입력 이벤트부터 캔버스 접근성 위치 변경까지이며 물리적 화면 표시 지연은 포함하지 않는다. 평지에서 오른쪽을 약 2.2초 유지하고 서버 응답까지 기다렸다.

| 모의 응답 지연 | 첫 위치 변경, 두 실행 | 연속 위치 변경 간격 | 최대 동시 요청 |
| --- | --- | --- | --- |
| 150ms | 35ms, 133ms | 대부분 80–147ms; 끝의 화면 경계 구간 276–293ms | 1 |
| 600ms | 117ms, 55ms | 대부분 약 74–140ms; 초기 구간에서 206ms 또는 547ms | 1 |

두 실행 모두 화면에서 서버가 보고한 최종 위치와 일치했다. 긴 입력 구간의 600ms 지연에서는 5개 요청으로 방향을 묶었다. 한 실행은 초기에 브라우저 long task 175ms·250ms가 관찰됐으며 다른 실행에서는 50–62ms가 관찰됐다. 150ms 실행의 이동 중 long task는 없었다. 표본이 작고 기기·서버·배포 네트워크가 모의 환경이라 원인별 개선 효과나 운영 체감으로 일반화할 수 없다. 구역 경계와 긴 지연에서의 멈춤, 첫 입력까지의 편차는 계속 확인해야 한다.

이번 시험에서 단일 코드 변경의 효과를 입증하지 못해 이동 로직은 변경하지 않았다. 다음 비교는 동일한 실제 기기의 브라우저 성능 기록과 네트워크 왕복, 필드 조우·구역 전환을 함께 기록해야 한다. 운영 데이터와 Sites 배포는 건드리지 않았다.

맵 대조 시 [구역 11 원작 설명](https://bulbapedia.bulbagarden.net/wiki/Wild_Zone_11)의 운하 양안과 [미션 28의 서쪽 옥상 동선](https://www.thonky.com/pokemon-legends-z-a/main-mission-28-a-rogue-mega-altaria)은 현재 각각 `adventure-zone11.mjs`, `adventure-magenta-sector4.mjs`에 초안으로 존재함을 확인했다. 자료만으로 구체적 타일·높이 차를 새로 결정할 수 없어 구조 완성으로 판정하거나 임의로 변경하지 않았다. 미션 10의 동료 더블 배틀은 `ADVENTURE_MISSION10_DOUBLE_PENDING.md`에 기록된 별도 핵심 미완성이다.
