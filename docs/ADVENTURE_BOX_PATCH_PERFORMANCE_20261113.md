# 이동 응답의 보유함 병합

부분 응답을 받을 때마다 전체 보유함으로 새 `Map`을 만드는 대신, 불변 배열별 개체 ID 인덱스를 약한 참조로 재사용한다. 실제 수정 대상만 기존 개체와 병합하고 보유함 배열 순서, 신규 개체 추가, 교환으로 떠난 개체 제거를 이전과 같이 처리한다. 중복 ID가 있는 구형 배열은 이전 `Map` 병합 경로로 처리한다. 서버 응답·이동·충돌·저장과 원작 규칙은 바꾸지 않는다.

동일 Node.js v24.19.0 프로세스에서 5,000개 보유 개체에 한 개체의 부분 응답을 2,000회 연속 병합하는 합성 검사에서 기존 1,285.5ms, 새 방식 15.6ms였다. 새 인덱스를 처음 만드는 비용이 포함된 반복 측정이지만 브라우저 렌더링·네트워크·D1은 포함하지 않는다. 실제 이동 지연이나 체감 개선을 입증한 수치는 아니다.

단위 검사로 연속 갱신·추가·삭제·중복 ID·ID 누락에서 기존 결과와 일치함을 확인했다. 격리 SQLite API에서 동시 이동, 커밋 리비전, 조우·저장, 늦은 요청 펜스 및 교환을 대표 회귀 검사했다. 운영 환경과 실제 브라우저 프레임·두 탭 경합은 이 변경으로 검증하지 않았다.
