# Tidy Up order investigation — 2026-11-18

Pinned source declares Tidy Up with RemoveArenaTrapAttr (PRE_APPLY) and RemoveAllSubstitutesAttr (POST_APPLY): [move](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/data/moves/move.ts#L11873), [hazard trigger](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/data/moves/move.ts#L6530), [substitute removal](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/data/moves/move.ts#L6359). Source sorts active Pokémon in speed order for substitute removal.

A temporary isolated single-battle engine probe (Mew versus Snorlax, both with a substitute and spikes) reproduced the opposite log order locally: both substitutes ended, then the two hazards ended, then the user's Attack and Speed increased. Both hazards and both substitutes were actually removed. This is an event-order discrepancy, not evidence that the cleanup failed. No persisted user data or server was used.

No fix has been applied. The native move uses the combined cleanup result to decide success when boosts cannot increase; moving hazard removal blindly to an earlier hook could incorrectly turn a successful cleanup into a failed move. Source substitute order and max-stat/no-substitute/no-hazard, blocked move, double battle, save restore and native success behavior need targeted tests before a safe fix.

Separate source inspection confirms Rapid Spin's Speed increase goes through the source's ability-adjusted move chance. Sheer Force sets that chance multiplier to zero, consistent with the existing test; no Speed-rule change was made. [ability definition](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/data/abilities/init-abilities.ts#L886), [chance adjustment](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/data/abilities/ab-attrs.ts#L1179).

## Follow-up implementation

New runs carry `tidyUpOrderRule: source-v1` into each combat. The move's per-use callback removes the four source hazard types from both sides before invoking the existing native callback for substitute removal and boosts. If that early removal was the only successful effect, the wrapper preserves success. The original per-use callback is restored afterward. Runs without the rule keep their prior order; existing data is not migrated.

In isolated engine tests the prior order test failed before the fix. Afterward single and double battle ordering, both hazards and substitutes, max stats including Contrary, no-cleanup/no-boost failure, substitute-only success, sleep and Taunt, new-run gating, an actual turn, PP, serialized save/restore and unrelated stored values passed. The five-file hazard, spin and fog regression run passed 41 tests; the follow-up Tidy Up suite passed 9 tests including Taunt. No browser, real devices, Z-move variants, all abilities, original speed-tie RNG or every multiple-substitute speed ordering were validated. In particular, native ordering among multiple substitutes has not been changed to the source's speed order; this remains a separate difference. No live server or user save was used.

## Substitute order follow-up

For new runs, `tidyUpSubstituteOrderRule: source-v1` orders the move's active-substitute pass by the native engine's current action speed, which includes stat stages and Trick Room. The temporary active-list override applies to only the first list lookup inside that move and is restored in `finally`; older runs without the rule keep their former side order. The separate hazard-order rule remains unchanged.

Pinned source [sorts by effective speed and Trick Room](https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/utils/speed-order.ts#L19), with an independent turn-seeded shuffle for ties and a separate explicit set-order override. This implementation deliberately retains the native relative order for equal action speeds, without consuming battle RNG; it does not implement the original tie shuffle or source set-order mechanism. Differences between the native engine's action-speed calculation and source speed calculation at exceptional speeds or special effects are not ruled out.

The new isolated tests reproduced the prior side-order discrepancy and cover single and double battles, Trick Room, a Speed boost, equal-speed stability, seeded battle RNG preservation, Taunt, legacy runs, a real move command and encoded save/restore. The six-file related suite passed 51 tests; the additional four-actor Trick Room check passed in the subsequent 10-test substitute-order suite. Browser, real device, all abilities and source RNG parity are not verified. No running server or user save was used.
