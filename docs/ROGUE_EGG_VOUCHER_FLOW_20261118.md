# 알 교환권·부화 격리 흐름 검사

격리 SQLite의 실제 포켓로그 API와 전투 엔진에서 체육관 트레이너 승리 후 플러스 교환권 지급, 대화와 웨이브 보상 건너뛰기, 교환권 소비 및 알 다섯 개 획득을 연결했다. 승리 상대와 트레이너 조우는 시험용으로 구성했지만 교환권 지급과 알 생성은 실제 승리·뽑기 코드가 처리했다. 획득 알의 종류와 내용은 뽑기 결과를 그대로 사용했다.

부화 검사는 긴 자연 진행 대신 알의 남은 웨이브를 1로 바꾸고 다음 전투를 구성했다. 실제 승리로 부화시킨 뒤 다섯 결과와 저장 복원, 결과 일괄 확인, 중복 승리·뽑기·확인 요청과 교환권 부족 시 저장 불변, 확인 전후 코인 불변 및 다른 슬롯·탐험 저장 보존을 확인했다. 별도의 기존 신규 이로치 환급 API 검사와 알 교환·이벤트 알·유전기·중복 환급 대표 검사도 통과했다. 첫 작성 시 미생성 알 배열과 승리 후 대화를 시험 절차에서 고려하지 않아 실패했고, 각각 빈 배열 처리와 실제 대화 건너뛰기 요청을 반영해 다시 통과했다.

처음부터 자연 진행해 트레이너를 만나는 과정이나 알의 모든 잔여 웨이브를 실제로 플레이한 것은 아니다. 모든 알·보상 조합, 운영 저장, 브라우저·실기기는 이 검사에서 검증하지 않았다. 이 표본에서 추가 게임 결함은 재현되지 않아 게임 로직은 변경하지 않았으며 Sites에 배포하지 않았다.

최종 웨이브 경계: 이전에는 원본 근거가 미확인이었다. 고정 원본 `7c0881255af5cd51992e513ff93c2f71adbe40e0`의 `VictoryPhase`는 클래식 최종 웨이브가 아닐 때만 `EggLapsePhase`를 예약하며, `EggLapsePhase`는 알의 잔여 웨이브를 줄인다. 현재 클래식의 200웨이브 제외는 이 경계에 부합한다. 격리 저장으로 199웨이브 부화·중복 호출 방지와 복원 후 200웨이브 미진행, 다른 슬롯과 탐험 데이터 보존을 확인했다. 200웨이브 자연 플레이나 원본 런타임 실행은 하지 않았다.
