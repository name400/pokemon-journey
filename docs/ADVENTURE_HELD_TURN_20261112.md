# 지연 중 방향 전환 예측

첫 이동 요청의 응답을 보류한 채 평지에서 오른쪽으로 네 칸을 표시한 뒤 위쪽 입력을 350ms 유지했다. 로컬 Chromium 390×844와 모의 `/api/world`를 사용했으며 캔버스의 접근성 위치를 관찰했다. 변경 전 한 칸, 변경 후 한 실행에서 세 칸이 표시됐다. 이는 픽셀 단위의 프레임 시간이나 실제 운영·휴대폰 지연 측정이 아니다.

변경 후 화면에 표시한 방향들을 기존 제한 안에서 순서대로 버퍼에 기록하며, 앞선 요청이 서버에서 확인될 때만 다음 경로를 전송한다. 서버가 전투·포획·장애물·불완전 이동을 반환하거나 요청이 실패하면 기존 중단·복구 경로가 우선한다. 자동 경로 찾기를 추가하지 않았다.

회전 중 보간, 지역 경계 및 실제 환경의 RTT·프레임 지연은 별도 측정이 필요하다.
