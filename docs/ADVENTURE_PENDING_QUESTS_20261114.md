# 진행 중인 의뢰 안내

[원작 미션 안내](https://www.powerpyx.com/pokemon-legends-z-a-all-side-mission-locations-main-missions/)는 수락한 의뢰와 목표를 미션 목록에서 확인할 수 있다고 설명한다. 기존 여행 수첩은 미션 5의 세 의뢰 진행 상태와 여러 사이드 의뢰의 목적지를 표시하지 않아, 이동 후 일지가 덮이면 다시 찾아가기 어려웠다.

현재 월드의 저장된 단계에서 미션 5의 파르빗·교환·묘지 의뢰, 시작한 14·21·27·72·74·88·119번 의뢰와 일부 명시적인 미수령 보상을 읽어 안내한다. 완료된 의뢰는 목록에서 숨기되 보상 대기 플래그가 실제로 있는 경우에는 수령 위치를 표시한다. 저장 데이터를 쓰거나 과거의 누락된 보상을 추정하지 않는다. 위치와 세부 단계는 현재 2D 게임 구현에 맞춘 안내다.

이는 원작 전체 119개 의뢰의 목록, 지도 표식 또는 추적 기능을 구현한 것이 아니다. 순수 함수에서 구형 저장·진행·완료·중복 기록·명시적 보상 대기를 확인하고, 격리 SQLite API에서 의뢰 수락·완료에 따른 표시를 확인했다. PC·모바일 Chromium은 모의 API로 표시와 새로고침을 검사했다. 운영 D1과 원작 기기는 확인하지 않았다.

## 의뢰 목표 추적

수첩에서 진행 중인 의뢰 하나를 추적하면 필드의 목표 문구가 해당 단계에 따라 바뀐다. 메인 미션으로 수동 전환할 수 있고, 선택한 의뢰가 완료돼 목록에서 빠지면 문구는 자동으로 메인 목표로 돌아간다. 선택 ID는 월드 리비전 조건으로 저장하며 실제로 표시 가능한 의뢰만 선택한다. 저장된 ID가 더 이상 유효하지 않거나 없는 옛 저장은 메인 목표를 표시한다. 자동 전환은 표시만 바꾸며 과거 저장이나 보상을 수정하지 않는다. 같은 ID의 반복 가능한 보상이 다시 생기면 사용자가 메인 미션을 선택해 추적을 해제할 수 있다.

원작의 목표 선택을 현재 2D 진행 화면에 옮긴 것이며, 지도상의 방향 표시나 목적지 경로 탐색은 추가하지 않았다. 비추적 상태의 이동 화면은 의뢰 목록을 생성하지 않는다. 격리 SQLite API에서 유효·무효 선택, 재접속, 오래된 리비전, 완료 후 기본 목표 복귀와 선택 해제를, PC·모바일 모의 브라우저에서 선택·복원과 문구 변경을 확인했다. 운영 D1과 원작 기기는 확인하지 않았다.

## 현재 구역의 의뢰 목적지

추적 중인 미션 5 필수 의뢰 세 건은 현재 구역에 해당 목표가 있으면 필드의 상호작용 칸 위에 표식을 표시한다. 파르빗 의뢰는 수락·골목·보고 단계에 따라 루주 6번지 또는 기존 구역 3의 위치를, 교환은 팔레 통로 또는 기존 구역 3의 Tracie를, 묘지 의뢰는 깜까미 현장 또는 서쪽 입구의 Moire를 가리킨다. 교환·묘지의 명시적 미수령 보상도 포함한다. 현재 구역이 다르거나 구형 옥상·학원 층에 있거나 대상 타일이 바뀌면 표시하지 않는다. 표식의 위치는 이 게임의 기존 2D 배치이며 원작의 정확한 좌표가 아니다.

기존 의뢰 14·72·74·88도 같은 방식으로 현재 구역의 목표를 표시한다. 이는 전체 도시 경로 탐색이나 다른 구역의 방향 안내가 아니다. 저장·진행과 이동 처리를 바꾸지 않으며, 구형 저장은 선택한 추적 ID와 이미 저장된 단계만 읽는다. 실제 맵과 구형 직렬화 저장, 단계별 전환·완료 및 다른 층을 단위 검사했고 PC·모바일 Chromium은 모의 API 화면을 확인했다. 원작 기기와 운영 환경은 확인하지 않았다.

## 식당 미수령 보상

르 나·르 와우·스시 하이 롤러는 최초 코스 또는 재도전 코스를 마친 뒤 보상 대기 상태가 명시적으로 저장된 경우 여행 수첩에 수령 장소를 표시한다. 목표를 추적하면 기존 실외 입구와 해당 식당 실내 안내원에 표식이 표시된다. 다른 층·구역과 루주 남쪽 거리에서는 표시하지 않으며, 옛 저장의 완료 여부만으로 보상을 추측하지 않는다. 보상을 받으면 수첩에서 사라지고 메인 목표로 돌아간다. 저장 형식이나 보상 지급·이동 처리를 바꾸지 않는다.

원작의 식당 코스와 보상은 [르 나](https://bulbapedia.bulbagarden.net/wiki/Restaurant_Le_Nah), [르 와우](https://www.serebii.net/legendsz-a/sidemissions/fullcourseofbattles:threestars.shtml)를 참고했다. 표식은 이 게임의 임시 2D 배치에 대한 길 안내이며 원작 지도 좌표가 아니다. 실제 보상 대기·수첩 선택·재접속·수령 후 목표 복귀를 격리 API에서, 세 식당의 실내외 표식과 다른 층·구형 저장을 단위 검사했다. 실제 기기와 운영 환경은 검증하지 않았다.

## 가방에 보관된 의뢰 보상

사이드 미션 117·118과 구역 15 홀로베이터 의뢰를 완료했을 때 가방 한도로 보관된 도구가 있으면 여행 수첩에 각각 보상 항목을 표시한다. 항목을 추적하면 가방에서 공간을 확보하고 보관 보상을 수령하라는 목표가 나오며, 수령이 끝나면 기존 메인 목표로 돌아간다. 기존 가방의 수령 버튼과 서버 지급·중복 요청 규칙을 그대로 사용한다.

완료 여부와 저장된 잔여 수량이 명시적이고 유효한 경우에만 표시한다. 옛 완료 저장에 보상을 추정해 만들지 않고, 잘못된 수량을 정상 보상으로 표시하지 않는다. 구역·실제 원작의 보상 보관 UI와는 별개인 이 게임의 가방 한도 대응이다. 격리 API에서 보관·부분 수령·재접속·중복 요청과 수첩 추적, 구형 저장을 대표 검사했다. 운영 D1과 Sites 병합본은 검증하지 않았다.

## 미술관 의뢰 층 안내

사이드 미션 21을 추적하면 이미 찾은 기록을 바탕으로 미술관 각 층에 남은 분떠도리 수를 보여준다. 구체적인 숨은 자리는 표시하지 않는다. 미술관 밖에서는 기존 입구를, 열두 마리를 찾은 뒤에는 2층 계단이나 1층의 Bundo·Wanda를 현재 층에 맞게 표시한다. [의뢰 공략](https://bulbapedia.bulbagarden.net/wiki/Walkthrough:Pok%C3%A9mon_Legends:_Z-A/Side_Missions_21-40)은 열두 마리를 찾고 의뢰인에게 돌아가는 흐름을 설명한다. 층별 수와 표식 좌표는 이 게임의 2D 맵을 기준으로 하며 원작 좌표를 재현한 것이 아니다. 알 수 없는 수집 ID가 있으면 층별 수를 추정하지 않고 기존 저장과 보상 처리는 변경하지 않는다. 실제 기기·운영 D1·Sites 병합본은 미검증이다.

## 최근 추적 의뢰의 수첩과 표식

사이드 미션 65와 81~86의 수락된 진행·명시적 보상 대기 단계를 여행 수첩과 목표 선택에 연결했다. 각 의뢰의 실제 2D 상호작용 지점이 현재 구역에 있으면 표식을 표시하며, 불켜미·데덴네 경유지와 구멍 조사는 저장된 단계에 따라 표식이 이동한다. 불켜미의 하수도 단계는 사용 가능한 베르날 입구 또는 하수도 목표에 표시한다. 다른 구역·층과 이미 완료된 의뢰에는 표식을 만들지 않는다.

미션 수락·목표 추적과 경유지에 대한 [원작 안내](https://www.powerpyx.com/pokemon-legends-z-a-all-side-mission-locations-main-missions/)를 참고하되 이 게임의 지도 좌표를 사용한다. 저장에 단계가 없거나 알 수 없는 단계라면 진행·보상을 추정하지 않는다. 전체 의뢰 표식과 다른 구역으로 가는 경로 탐색은 여전히 미구현이다.

단계별 표식·구형 및 비정상 저장·다른 층·완료 후 목표 복귀를 단위 검사했고, 격리 API에서 추적 선택·재접속·경유지 전환·중복 요청·완료를 확인했다. PC·모바일 Chromium에서는 모의 API로 수첩 선택·표식·재접속·완료 화면을 확인했다. 실제 원작 기기·운영 D1·Sites 병합본은 미검증이다.
