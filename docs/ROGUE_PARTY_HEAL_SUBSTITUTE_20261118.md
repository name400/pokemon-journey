# Jungle Healing and Lunar Blessing: Substitute

The pinned source treats these moves as `USER_AND_ALLIES`, with target-directed HealAttr and HealStatusEffectAttr; its `hitsSubstitute` checks every target of those moves, including the user, and allows Infiltrator to bypass the Substitute. The move effect phase skips target effects when Substitute blocks the target. Source: https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/data/moves/move.ts#L488 and https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/phases/move-effect-phase.ts#L582.

The native simulator instead healed and cured both user and ally behind Substitute with Jungle Healing, and healed/cured the user with Lunar Blessing. The new-run `partyHealSubstituteRule: source-v1` checks each target before those effects, while keeping their existing rounding and normal/passive Infiltrator behavior. It is battle-local and stored with combat; old runs keep their previous behavior. This follows the pinned source behavior rather than asserting equivalence with another Pokémon game's mechanics.

Sequential isolated tests: 42 passed. They cover user and ally Substitute, unshielded recipients, both moves, single and double battles, attacker and enemy sides, normal and passive Infiltrator and suppression, actual player command, save codec and separate data, legacy behavior, rounding and Heal Bell/Aromatherapy regression. Full source runtime, all combinations (including Z/Max and caller variants), browser and real devices were not tested. Existing user data and servers were not used; Sites was not deployed.
