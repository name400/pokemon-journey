# 포켓로그 더블 전투 강제 교체·상태 이상 검사

2026-11-17 개발본의 실제 포켓로그 API를 격리 SQLite 저장과 실제 전투 엔진에 연결해 검사했다. 시험용 포켓몬과 전투 상태를 만들었으며 운영 계정이나 기존 저장은 사용하지 않았다.

- 독 피해로 한 출전자가 기절할 때 피해 이벤트가 기절보다 먼저 나오는지, 화상 동료와 마비된 예비 포켓몬·각 도구·기술 PP가 재조회와 강제 교체 뒤 보존되는지 확인했다. 오래된 턴 요청은 409로 거절되고 저장이 변하지 않았다.
- 교체 전 전투 스냅샷에 독압정을 주입한 격리 조건에서 교체 이벤트 뒤 독 상태 이벤트가 발생하며, 통굽부츠를 지닌 교체 대상은 독에 걸리지 않는 것을 확인했다. 두 경우 모두 재조회한 엔진 상태와 도구를 검사했다. 독압정의 자연스러운 설치 경로 자체를 이번에 검사한 것은 아니다.
- 두 출전자가 독 피해로 기절하고 예비가 하나뿐일 때 두 피해·기절 이벤트, 한 슬롯의 교체 요청과 다른 슬롯의 대기, 재접속 뒤 유일한 교체와 재전송 거절을 확인했다. 마비·도구와 기절 상태, 다른 저장 슬롯과 탐험 데이터를 보존했다.

별도로 기존 강제 교체 부족·기절·유턴과 울부짖기·상태 피해 순서·진입 장해물·도전 제한의 엔진 검사 22건과 신규 API 검사 3건이 통과했다. 이번 조건에서는 추가 결함이 재현되지 않아 게임 규칙은 바꾸지 않았다. 모든 상태 이상·복수 특성·도구·강제 교체 기술과 실제 기기·운영 저장은 미검증이다. 시간 정지 기능은 비활성 상태이며 Sites에는 배포하지 않았다.

## 실제 기술 설치부터 교체까지 추가 검사

이전의 독압정 스냅샷 주입과 별도로, 격리 포켓로그 API에서 더블 트레이너 전투의 두 상대가 실제 독압정·스텔스록 기술을 각각 사용하도록 했다. 설치 이벤트와 사용 PP, 저장·재조회 후 양쪽 장해물을 확인하고 플레이어가 교체했을 때 이벤트와 상태를 검사했다. 접지한 피카츄는 스텔스록 피해와 독, 리자몽은 타입에 맞는 스텔스록 피해와 독압정 면역, 통굽부츠 착용자는 둘 다 차단됐다. 이상해씨는 교체 시 독압정을 제거했고 상대가 같은 턴에 다시 설치한 것은 엔진 로그로 구분했다. 독에 걸린 개체는 해당 턴 말미 독 피해도 받는다.

별도 단일 트레이너전에서는 플레이어가 두 기술을 실제로 사용하고 재접속한 다음 울부짖기로 상대 예비 개체를 강제 교체했다. 기술→교체→피해·독 상태 이벤트와 타입별 스텔스록 피해, 세 기술의 PP, 재조회와 구 리비전 재전송 거절을 확인했다. 두 시험 모두 다른 저장 슬롯과 탐험 데이터도 보존됐다. 사용한 상대와 기술은 격리 fixture로 구성했으며 실제 게임 액션으로 설치·교체를 실행했다.

처음 작성한 더블 검사의 HP 기대값은 턴 말미 독 피해를 누락했고, 독 타입의 흡수 뒤 상대가 독압정을 다시 설치하는 행동도 누락했다. 전투 로그를 대조해 두 시험 조건을 바로잡았다. 이는 게임 결함의 증거가 아니다. 관련 자연 설치 API 2건과 기존 강제 교체 API 3건 중 대표 검사, 장해물·전투 경계 엔진 검사 14건이 통과했다. 모든 기술·특성·다중 전투 조합과 실제 기기·운영 환경은 미검증이며 Sites에 배포하지 않았다.
