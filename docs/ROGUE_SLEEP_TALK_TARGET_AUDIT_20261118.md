# Sleep Talk target audit

An isolated doubles fixture using a Comatose user showed that the current game view exposes Sleep Talk as `target: self` with no target choices. The pinned source sets Sleep Talk to `MoveTarget.NEAR_ENEMY`: https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/data/moves/move.ts#L10084.

This is a confirmed target metadata difference, not yet proof of a particular resulting damage target. Source `CallMoveAttr` explicitly does not preserve the initial target for Sleep Talk; it selects eligible targets for the called move separately: https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/data/moves/move.ts#L7822. The current native move targets the user and its calling handler receives that user as its first argument. Changing only the request target or native move target can change hit checks, callbacks, execution and legal inputs. The source's handling of Protect, substitute, immunity, switching/fainting, self/ally/spread called moves, AI, same-turn choices and save restoration needs verification before a safe compatibility-gated change.

No implementation change was made. The fixture was an in-memory trainer double battle with a Comatose user; no server or user data was used. Original source execution, browser, and the listed boundaries were not tested. Sites was not deployed.

## Follow-up implementation

Source `MoveEffectPhase.start()` applies the move-calling override before ordinary hit/protect checks, and the called move gets its own separately selected targets: https://github.com/pagefaultgames/pokerogue/blob/7c0881255af5cd51992e513ff93c2f71adbe40e0/src/phases/move-effect-phase.ts#L112. New runs with both `sleepTalkTargetRule: source-v1` and the existing source calling policy present living opposing targets in doubles. The command validates that selection but does not pass it as the called move's target to the native self-targeted Sleep Talk; the current independent calling engine remains responsible for the called move. Single battles and runs without the new flag retain previous input behavior. The rule is saved with combat state.

Tests exercise actual `playClassicCombat` doubles target choices, invalid target rejection, the same deterministic called attack outcome for both selections, self-healing, PP, new runs, single battles, legacy runs, and codec recovery. Separate native engine command tests exercise a Protecting foe and a foe switching before the call; these do not establish every queued command/target disappearance combination in the full API. Called move and sleep regression suites total 38 passing tests. Actual source execution, browser/real device, opponent AI target-selection equivalence, all special forms/Z/Dynamax, field/status effects and the visual event target remain unverified; native PRNG is not claimed identical to source. No production data or server was used, and Sites was not deployed.

Browser follow-up: an owner-token-checked, dedicated Vite fixture server and in-memory synthetic save were used with headless Chromium at 390×844 and 1280×800. The user could select the second opponent for Sleep Talk, complete the ally's command and submit the actual turn; Sleep Talk appeared in returned events and the synthetic save remained unchanged after reload. Both passed without browser page errors. This is not an actual-device or full target-disappearance/AI validation.
