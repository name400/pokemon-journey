# 순서 있는 이동 예측 — 기반 단계

기존 `predictCloudPath`와 같은 규칙으로 각 중간 칸을 반환하는 `predictCloudPathSteps`를 추가했다. 같은 종점으로 돌아가는 서로 다른 경로도 구분하며, 막힌 칸과 구역 전환에서 기존처럼 멈춘다. 기존 함수는 마지막 칸을 반환하므로 기존 호출과 저장 형식은 그대로다.

`confirmedCloudPathPrefix`는 요청에서 보낸 칸 수와 시작 리비전을 명시적으로 받아, 정확한 다음 리비전·걸음 수·위치·방향과 같은 지역·파트너를 확인한 경우에만 확정 접두부와 남은 칸을 나눈다. 같은 위치를 반복 방문해도 좌표 검색 대신 요청 칸 수로 분리한다. 불일치, 중복 응답, 전투·조우·포획 대기·기술 학습 대기, 위험 예측과 층 전환은 모두 `null`로 거절한다. 실제 경합·실패 복구는 호출자가 권위 상태를 다시 받아 큐 전체를 폐기해야 한다.

이 단계는 함수와 단위 검증만 제공한다. **서버 응답, 그리기 큐와 연결되지 않았고 지연이나 화면 이동은 개선되지 않았다.** 기존 브라우저 이동·조우·복구 검사는 기존 동작의 회귀 확인이며 새 확인 함수를 사용한 검사가 아니다. 다음 단계에서 요청별 순번 및 취소 세대, 실제 이동 응답·다른 탭 경합을 연결하고 렌더링·D1 대표 사례와 동일 입력 전후 측정이 필요하다. 운영 데이터와 Sites는 사용하지 않았다.
