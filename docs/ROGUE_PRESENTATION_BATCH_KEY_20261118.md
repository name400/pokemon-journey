# 전투 연출 묶음 식별자와 재생 키

기존 화면 재생 키는 도전 ID·웨이브·턴·이벤트 내용·결과만 사용했다. 확정된 서로 다른 두 이벤트 묶음이 같은 턴에 같은 내용을 가지는 격리 구성에서 서버의 묶음 ID는 다르지만 화면 키가 같아, 앞선 묶음을 이미 재생한 상태라면 뒤 묶음을 별도 재생으로 식별하지 못했다. 이 구성은 확정 함수와 화면 키를 직접 연결한 시험이며 자연 플레이에서 같은 상황이 발생하는 빈도는 확인하지 못했다.

유효한 묶음 ID와 이벤트 ID 배열이 응답에 있을 때 화면 키에 묶음 ID를 포함한다. 이벤트 내용도 계속 포함한다. 구형 저장과 형식이 잘못된 메타데이터는 기존 키를 사용한다. 게임 저장·판정·보상·연출 확인 장부 및 서버 API는 변경하지 않았다. 완료한 연출을 새로고침 후 생략하지 않으므로 재접속 연출 반복 문제는 여전히 미해결이다.

수정 전 격리 테스트에서 별도 묶음의 키가 같다는 실패를 확인했고, 수정 후 구형·잘못된 메타데이터와 저장 직렬화·대화 대기 검사 등 연출 단위 검사 14건이 통과했다. 격리 SQLite의 실제 전투 요청·재조회, 승리 및 포획 경로 3건도 통과했다. API 요청 응답과 재조회의 동일한 묶음 키를 비교했다. 두 개의 동일 내용 묶음 생성은 시험 구성이고 실제 브라우저·실기기에서 이 상황을 재현하지 않았다. 변경 파일의 부분 ESLint는 통과했으며 전체 타입 검사와 전체 린트는 이번 변경 후 실행하지 않았다.

전용 소유권·포트를 확인한 격리 Chromium의 구형 메타데이터 없는 단일 전투에서 등장 완료 뒤 새로고침하면 등장 두 건이 다시 재생됨을 재확인했다. 움직임 줄이기 후 원래 설정 복귀와 백그라운드 중단 후에도 미확인 등장이 다시 재생됐고, 복제 탭에 진단용 세션 기록이 복사되는 것도 확인했다. 이 브라우저 검사는 신형 묶음의 동일 내용 충돌이나 실기기 검사가 아니다. 중복 억제는 계속 적용하지 않는다.
