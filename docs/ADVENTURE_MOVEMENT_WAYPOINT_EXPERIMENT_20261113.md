# 방향 전환 중간점 실험

기준 `b0b39678`. 이전·다음 예측이 같은 리비전에서 인접한 경우, 직전 예측 위치를 화면에 전달하고 필드가 이전 표시 목표·중간점·새 목표가 각각 인접할 때만 두 구간으로 보간하는 후보를 로컬에서 시험했다. 서버 응답의 위치 보정에는 중간점을 붙이지 않도록 했다. 이 후보는 실험 후 제거했으며 게임 동작은 변경하지 않았다.

동일한 로컬 Chromium 390×844, 모의 600ms 이동 응답, 오른쪽 입력 후 위쪽으로 전환하는 시험에서 전환 시간을 395·405·415·425ms로 바꿨다. 모든 사례의 최종 모의 서버·화면 좌표 및 경로 걸음 수는 일치했고 요청은 직렬이었다. 후보 전 기록에서는 긴 사례 하나가 논리 위치 (7,8)→(7,7) 이후 185ms 동안 다음 목표가 없었고, 빨간 픽셀이 한 프레임에 (199,259)→(232,227)로 바뀌었다. 후보 적용 후 별도 실행에서도 (7,8)→(7,7) 이후 194ms 간격과 한 프레임 (193,259)→(232,227) 이동이 나타났다. 다른 입력 위상에서는 이전과 마찬가지로 약 100ms 간격이었다. 소표본이며 실행 간 입력·그리기 타이밍이 정확히 같지 않으므로 정밀한 성능 비교는 아니다. 다만 기대한 급격한 이동 제거는 이 후보에서 입증되지 않았다.

후보가 적용될 수 있는 조건과 React 렌더링에 전달된 중간점의 실제 순서는 계측하지 않았으므로 왜 실패했는지는 확정하지 않는다. 다음에는 예측을 생성하는 이벤트, 화면에 전달된 예측과 렌더된 프레임의 경로를 동일 시간축에서 기록하고, 누락된 중간점을 경로 자체로 보존하는 설계를 검토해야 한다. 서버 교정·충돌·조우 시 이를 즉시 폐기해야 하며, 시각 중간점을 서버에 새로운 이동으로 재전송해서는 안 된다.

브라우저는 실제 D1이나 물리 휴대폰이 아닌 모의 API와 대체 이미지를 사용했다. 후보의 충돌·조우·시간 초과에 대한 안전성은 확인하지 않았고, 기능 변경으로 반영하지 않았다. `testfailed.md`의 복구 경합과 실제 Sites 병합본 검사 미해결 항목을 유지한다.
